# 透明浮窗监控开发计划

## 目标

在 Electron 桌面版中增加轻量透明监控浮窗：设置页可开启/关闭，应用启动时按配置恢复；浮窗置顶显示关键市场和自选股摘要；主窗口顶部右侧快捷图标可显示/隐藏并支持右键快捷切换；系统托盘右键菜单提供同一开关。首版不新增外部数据源，不把完整实时页缩小复用。

当前代码没有独立垂直“右侧图标栏”，因此将需求中的右侧图标解释为主窗口顶部 `.header-actions`；系统托盘右键作为原生应用图标菜单入口保留。

## 首版监控数据（P0）

浮窗范围严格限定为两类内容：**实时行情**和**用户选择加入监控的自选股价格走势**。不显示市场宽度、涨跌停、板块、资金流、盘口异动、龙虎榜、新闻、复盘摘要或其它分析内容。

- 实时行情：显示交易状态、实时/最近交易/缓存口径、数据时间，以及现有实时行情中的主要指数（上证、深证、创业板）的现价和涨跌幅。
- 自选股价格走势：每只自选股提供独立的“加入监控浮窗”选项；仅展示用户明确加入监控的股票，按现有自选顺序排列，首版最多 5 只，显示名称、代码、现价、涨跌幅、更新时间和轻量价格走势（优先复用已有 K 线/报价数据，不展示其它指标）。
- 自选股监控选择与“是否为自选股”分离：移出自选股时自动从浮窗监控列表移除；新增自选股默认不加入浮窗。监控数量显示为“已选/5”，达到上限时未选股票控制禁用。
- 不生成市场强弱等级、温度或买卖方向判断；仅展示原始行情和价格变化，并标明数据仅供参考、不构成投资建议。

## 技术方案

1. **主进程窗口**（`src/desktop/electron-main.js`）
   - 新增独立 `monitorWin` 和窗口生命周期函数；使用 `transparent: true`、无边框、置顶、跳过任务栏、独立固定尺寸。
   - 通过 `?mode=monitor` 加载同一前端的专用监控模式，不能复用主窗口的全屏 bounds 逻辑。
   - 使用 `monitorEnabled` 表达启动恢复偏好，和当前 visible 状态分开；浮窗关闭默认隐藏，应用退出时才真正销毁。
   - 保存并校验 `monitorBounds`，处理多显示器、工作区、DPI 和显示器移除；位置越界时回到主显示器右上角。
   - 扩展托盘 `updateTrayMenu()`，加入“透明浮窗监控” checkbox。设置、顶部图标、托盘和浮窗均调用统一 `setMonitorEnabled()`，主进程作为状态权威并广播状态。
   - 浮窗显示的自选股不是全部自选股：每只自选股单独维护加入/移出状态，监控列表默认为空，且最多展示 5 只。

2. **数据调度**
   - 优先建立共享行情刷新路径：同一轮 `/api/realtime` 只请求一次，主窗口和浮窗消费同一份标准化 payload；浮窗可见且主窗口隐藏时仍能刷新。
   - 复用 `/api/realtime`、`/api/stocks`、SQLite 快照和现有交易时段/缓存口径，不让两个窗口各自高频轮询完整接口，避免东方财富限流。
   - 请求去重、超时和错误回退必须保留上一次有效数据，并明确显示缓存/过期状态；非交易时段不自动高频抓取。

3. **IPC 安全边界**（`src/desktop/preload.js`）
   - 仅暴露查询状态、设置启用、显示/隐藏/切换、打开主窗口、手动刷新和状态/数据订阅等窄接口。
   - 继续使用 `contextIsolation: true`、`nodeIntegration: false`；事件订阅返回解除监听函数；主进程校验发送方窗口。

4. **存储与 API**（`src/desktop/storage.js`、必要时 `server.js`）
   - 在默认设置中加入 `monitorEnabled: false`；新增受限的 `monitorWatchlist`（股票代码数组，默认 `[]`），记录每只自选股是否加入浮窗；若开放配置，再加入受限的刷新周期、显示数量、透明度和 bounds。
   - 复用现有 settings key-value JSON 存储和 `/api/settings`，对监控股票代码、布尔、数值、坐标、尺寸做前后端/主进程归一化；保存监控列表时必须与当前自选股求交集，不允许监控已移除的股票；不新增表。
   - 只有确认完整实时接口过重时才增加轻量监控 API，且服务端必须共享缓存/调度，不重复抓取。

5. **前端**（`src/desktop/frontend/index.html`）
   - 设置页在通知设置附近增加透明浮窗开关，说明置顶、显示内容和非交易时段口径；在自选股列表/卡片上为每只股票增加“加入/移出监控浮窗”控制，并显示当前监控数量/上限。
   - 顶部 `.header-actions` 增加监控图标：左键显示/隐藏，`contextmenu.prevent` 提供右键快捷切换；提供 title、aria-label 和键盘可用的左键入口。
   - `mode=monitor` 只渲染紧凑透明卡片、实时行情指数、自选股价格走势和隐藏/刷新/打开主窗口按钮；页面根透明、卡片半透明，支持明暗主题、拖拽和 focus-visible，不渲染其它市场分析模块。
   - 涨跌不能只依赖颜色，必须同时有正负号/文字；数据失败时展示最近有效数据和错误提示。

## 实施阶段

1. 抽取并测试监控 payload、派生摘要、缓存标识和交易时段标签，先确定共享刷新策略。
2. 增加设置默认值/校验，完成主进程浮窗状态机、bounds 恢复、托盘入口和广播。
3. 增加 preload 白名单，完成前端设置、顶部图标右键和专用透明模式。
4. 补充 storage/纯函数/IPC 状态机测试及 Electron 手工 smoke 验收。
5. 通过验证后只优化实时行情和自选股价格走势的显示与性能，不扩大浮窗数据范围。

## 测试与验收

- 在 `src/desktop` 执行 `npm run check`、`npm test`，必要时执行 `npm run desktop` 和打包验证。
- 自动化覆盖：默认关闭、设置保存/重启读取、非法值回退、摘要缺失字段、缓存与失败状态、涨跌家数零值、bounds 越界校正、启停幂等、托盘菜单状态和 IPC 广播。
- 手工覆盖：设置/顶部图标/右键/托盘四入口同步；主窗口隐藏后浮窗继续工作；重启恢复；浮窗关闭不退出应用；完整退出清理窗口和定时器；单屏/双屏/侧边任务栏/125% DPI；明暗主题；交易中、午休、闭市、无网络；小尺寸无溢出；浮窗透明、置顶、可拖动且不抢焦点。

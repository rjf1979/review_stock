# 2026-09-04 · stock-sentinel-ai 页面布局优化基线

GPT Terra 已完成 `src/stock-sentinel-ai` 桌面版前端布局/视觉优化。**后续所有页面/布局开发必须以此优化后的规则为基线。**

## 参考落地文件
- 布局与样式唯一真源：`src/stock-sentinel-ai/frontend/index.html`（内联 `<style>` + Vue 3 SFC 式模板，引用 `/vendor/vue.global.prod.js`、`/vendor/echarts.min.js`）。

## 设计 Token 体系（必须沿用，禁止硬编码随意色值）
- 语义色：`--bg` / `--bg-elevated` / `--bg-hover` / `--bg-active`、`--border` / `--border-strong`、`--text` / `--text-muted` / `--text-faint`。
- 强调色：`--accent` / `--accent-hover` / `--accent-soft` / `--accent-soft-strong` / `--accent-text`。
- 行情色：`--up`（涨）`--down`（跌）`--danger` / `--danger-soft` `--warn` / `--warn-soft`。当前暗色 `--up:#ff4545`（红）、`--down:#20b7c7`（青）。**注：早期用户明确要求「红涨绿跌」，当前 down 为青色，若需严格绿跌需再改 `--down` 为绿色并同步图表。**
- 焦点环：`--focus-ring` / `--focus-ring-inset`；键盘可见焦点必备。
- 层级阴影：`--shadow-sm` / `--shadow`；按钮渐变 `--btn-grad` / `--btn-primary-grad` / `--btn-primary-text` / `--btn-shadow` / `--btn-primary-shadow`。
- 形状/间距/字体：`--radius` / `--radius-sm` / `--radius-xs`、`--space-1..6`、`--mono`。
- 深色为默认 `:root`，浅色用 `@media (prefers-color-scheme: light)` 覆盖同一组 token。
- 动效尊重 `@media (prefers-reduced-motion: reduce)`。

## 布局与响应式规则
- 自适应全尺寸：`.shell` 用 `max-width:100%` + `clamp(...)` 内边距；内容宽度 `width:min(1400px, 96vw)`；窗口缩放/最大化均自适应。
- 栅格用 `grid + minmax + auto-fit`（概览卡、统计卡、规则参数），`flex-wrap` 兜底小屏。
- 断点：`@media (max-width:1080px)` → 详情工作区变单列、图表高度调整；`(max-width:768px)` → 控件全宽、表格 `min-width:620px` 横向滚动、设置/规则表单单列。
- 组件状态齐全：按钮/ chip 的 `hover / active / focus-visible`、`aria-pressed` 选中态、`.btn.primary` 主次、chip 选中描边。
- 表格：`.table-wrap` 内滚动、`thead th` sticky 顶、行 hover、数字列右对齐、涨跌用 `.pos`/`.neg`。
- 卡片/面板：`.panel`、`.card`、`.overview`、`.market-stats`、`.quote-stats`、`.settings-section` 均走同一 token。
- 详情弹层：宽 `min(1400px,96vw)`、高 `max-height:92vh`、可滚动。

## 交互与可访问性
- 所有可点元素为 button 或带 `tabindex="0"` + `@keydown.enter`；状态用 `role="status"` / `aria-live="polite"`；选中用 `aria-pressed` / `aria-selected`。
- 红色=涨、青色=跌的语义需全局一致（K 线、量能十字、文字、数字、图标），不得局部改色。

## AI研判落库与标记（2026-09-04 确定）
- 存储选 SQLite：`src/stock-sentinel-ai/data/kline.db`，不新增散文件。
- 口径：每只股票每个 `tradeDate`（研判所用 K 线截止日）只保留 1 份成功结论；同日再次成功会替换旧成功行并清理不再引用的价位集合；失败/格式异常尝试独立保留供“重试研判”。
- 读回接口：`GET /api/ai/record?code=600108` → `{ record, prevSuccess, lastFailed, levels, status }`；核心实现 `storage.writeJudgmentRecord` + `judgment-core.latestRecordForCode`。
- 前端详情弹框二次打开会回填历史结论/观察价位，标题旁显示标记：已研判 · 时间 / 待复核 / 研判失败 · 可重试 / 待研判；单股研判成功后调用 `loadPoolJudgments()` 同步候选池状态列。
- 颜色已按用户最新确认：红涨 `--up:#ff4545`、青跌 `--down:#20b7c7`，无需改回绿色。

## Prompt 读取故障复盘
- 专业操盘 Prompt 的唯一运行时数据源是 SQLite `ai_prompt_configs(id=1)`，文件路径必须以运行进程的 `VOLUME_INSIGHT_KLINE_DB` / `VOLUME_INSIGHT_DATA_DIR` 为准，不能只看默认 `data/kline.db`。
- 前端曾在 `settings` 初始 reactive 对象内嵌完整 Prompt fallback；`loadSettings()` 请求失败或加载顺序异常时，旧 fallback 会静默显示，造成“文本框与数据库不一致”的假象。
- 以后 Prompt 不得在前端保存第二份可见副本。初始化应为空，独立请求 `/api/ai/prompt` 后才赋值；请求失败必须显示错误状态，不得静默回退旧文本。
- 排查此类问题必须逐字/Hash 对比三层：运行时 SQLite、`/api/ai/prompt` 响应、页面加载后的 reactive 值；同时确认 3110 进程实际数据库环境变量和静态页面版本。
- Prompt 版本只允许内部 `current`，不得在正文、HTML 注释、fallback 或接口参数中重新引入 `v1`/`v2` 标记。

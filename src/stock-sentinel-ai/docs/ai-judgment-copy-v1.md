# 批量 AI 研判与二次研判 · 产品与界面文案 v1（待实施）

> 日期：2026-09-04  
> 范围：定义“候选池批量 AI 研判 + 个股二次研判（增量复核）”的产品口径、数据就绪条件、页面与状态文案、AI 证据与输出结构；暂不改研判接口、前端交互与数据源。  
> 用途：本稿不是现状说明。批量接口、结果落库、证据摘要、题材/事件数据完成接线并回归前，不得将对应文案落到生产界面。与 `scoring-copy-v1.md` 配套使用，三维评分口径以该稿为准。

## 1. 一句话口径

候选池中的股票达到“完整就绪”或“有限就绪”后，可一次对多只发起 AI 辅助研判；已经研判过且证据发生变化的股票再次研判时，携带上次结论、证据日期和变化项做**增量复核**，输出“维持 / 修正 / 新增变化 / 无法研判”。相同证据不重复调用模型。批量研判与二次研判只辅助人工复核，不自动买入、不自动转入自选、不构成投资建议。

## 2. 流程说明（候选池页顶部推荐文案）

```
全市扫描 → 命中股票先纳入候选池
候选池补齐研判数据（K 线 + 当日快照；题材/事件数据随接线进度扩展）
批量 AI 研判（首次研判 / 失败重试 / 证据已更新；无变化与未就绪项自动跳过）
单只复核 / 二次研判（证据变化后，对比上次结论做增量复核）
复核后转入自选盯盘（持续跟踪，数据变化后再研判）
```

> 与 `scoring-copy-v1.md` 的关系：候选池补齐从“K 线补齐”逐步扩展为“K 线 + 题材/行业 + 事件”等研判数据补齐；三维综合评分上线前，候选排序仍按现有量能分口径。

### 4.3 二次研判输出（增量结论）

二次研判结果分为三块，界面用固定小标题便于对比：

```
维持上次判断：新增证据未改变上次结论。
修正上次判断：证据 XX 发生变化，倾向由 A 调整为 B，原因是 …
新增关注点：今日出现的新信号/新题材/新事件，建议跟踪 …
```

- 若证据没有变化（如同一交易日重复打开），由本地显示“无新增证据，上次判断保持不变”，不调用模型。
- 首次研判完整输出一次；二次研判优先输出增量，完整原文仍可展开查看。

### 5.1 技术指标实施口径

首版新增指标只选择能补充趋势强度、波动风险、相对表现和量价确认的信息，不重复堆叠同类震荡指标：

| 指标 | 固定参数与输出字段 | 最小样本 | 研判用途 |
| --- | --- | --- | --- |
| ATR | `ATR14`、`ATR14Pct = ATR14 / close × 100` | 15 根 | 衡量绝对与相对波动；只描述风险水平，不生成买卖价位 |
| BOLL | `BOLL20`、2 倍标准差；输出上/中/下轨、`percentB`、`bandwidth`、带宽方向 | 20 根 | 判断收口、扩张及价格所处通道位置 |
| ADX / DMI | `ADX14`、`plusDI14`、`minusDI14`、方向状态 | 28 根 | 区分趋势与震荡，并判断趋势方向是否得到强度确认 |
| 相对强弱 RS | 个股相对所属行业和对应宽基指数的 `RS20`、`RS60` | 61 个共同交易日 | 判断个股是否真正跑赢行业与市场，不以单只涨跌幅替代 |
| OBV | `OBV`、20 日标准化斜率、价格/OBV 背离状态 | 21 根 | 验证价格趋势是否获得成交量确认 |
| 量能历史分位 | 成交量、成交额、换手率的 20/60 日分位 | 对应窗口 | 区分普通活跃与历史异常量能 |

第二阶段可选增加 `ROC20/ROC60` 和 `MFI14`，用于观察中期动量变化与量价结合的资金强弱。KDJ、WR、CCI、多套 MACD/RSI 参数和主观画线指标不进入首版，避免与现有 RSI、MACD、形态规则重复表达和重复加权。

### 5.2 指标计算与使用边界

1. 所有日线指标使用同一套前复权、升序 K 线，并记录 `adjustmentType`、K 线截止日期和算法版本；复权版本变化必须触发重新计算。
2. 相对强弱必须将个股、行业指数与对应宽基指数按共同交易日内连接后计算；日期不一致、基准缺失或共同样本不足时返回 `null`，不得错位补值。
3. 历史回放只能使用目标日期当时已经产生的数据，禁止引用未来 K 线、后来更新的行业归属或尚未发布的数据。
4. 指标输出使用 `value + state + trend + available` 结构；AI 读取状态摘要，不接收完整指标数组。
5. 技术指标作为形态确认和风险修正证据，不直接累加进三维综合评分；多个相关指标同时出现时不得按数量重复增强结论。
6. “主力净流入”为数据供应商估算字段，必须携带来源和日期，并与量价趋势交叉验证，不作为单独定论依据。

固定计算定义如下，首版不得由不同调用方自行更换公式：

- `ATR14`：真实波幅 `TR = max(high-low, abs(high-prevClose), abs(low-prevClose))`，使用 Wilder 14 日平滑；`ATR14Pct = ATR14 / close × 100`，收盘价无效时返回 `null`。
- `BOLL20`：中轨为 `SMA20(close)`，标准差采用 20 日总体标准差，上下轨为中轨 `± 2σ`；`percentB = (close-lower)/(upper-lower)`，`bandwidth = (upper-lower)/middle`。分母为 0 时对应字段返回 `null`。
- `ADX14/DMI14`：`TR`、`+DM`、`-DM` 均使用 Wilder 14 日平滑；`ADX < 20` 为震荡，`20～25` 为趋势形成，`>25` 为趋势确认，方向由 `+DI` 与 `-DI` 的大小确定。
- `RSn`：个股和基准按共同交易日对齐后计算 `((close_t/close_t-n)/(benchmark_t/benchmark_t-n)-1) × 100`，单位为相对超额百分比；行业和宽基指数分别计算，不混成一个值。
- `OBV`：上涨日加当日成交量、下跌日减当日成交量、平盘不变；`slope20` 为最近 20 日 OBV 线性回归斜率除以同期平均成交量。价格与 OBV 在同一 20 日窗口方向相反时标记背离。
- 历史分位：在对应 20/60 日有效窗口内计算 `小于或等于当前值的样本数 / 有效样本数 × 100`；有效样本不足窗口时返回 `null`，不缩短窗口伪装完整分位。
- BOLL 带宽方向：当前带宽相对最近 5 个有效带宽均值高出 10% 以上为 `expanding`，低 10% 以上为 `contracting`，其余为 `stable`。

### 5.3 观察价位与触发标记

支撑、压力和触发价位必须由本地确定性算法计算，AI 只解释价位依据，不得自行生成、移动或补全价格。界面统一使用“观察价位”口径，不使用确定性的“买入点 / 卖出点 / 目标价”。

| 标记 | 定义 | 界面文案 |
| --- | --- | --- |
| 支撑区 `supportZones` | 波段低点、MA20/MA60、BOLL 中下轨、平台/箱体边界、缺口边界等相近价位聚合后的区间 | 支撑观察区 |
| 压力区 `resistanceZones` | 波段高点、20/60/120 日前高、BOLL 中上轨、平台/箱体边界、缺口边界等相近价位聚合后的区间 | 压力观察区 |
| 入场触发 `entryTriggers` | 回踩确认或放量突破的条件组合 | 入场观察条件 |
| 结构失效 `invalidationLevel` | 有效支撑下沿减去波动缓冲后的风险参考线 | 结构失效位 |
| 退出观察 `exitWatchZones` | 下一压力区、移动保护线或结构转弱条件 | 退出观察区 |
| 空间评估 `riskReward` | 下一压力区潜在空间与失效位风险距离之比 | 观察空间比 |

首版固定算法口径：

1. 在最近 120 根有效日 K 内，用左右各 3 根 K 线确认局部波段高低点；最后 3 根尚未确认的拐点不参与计算。
2. 合并波段高低点、20/60/120 日区间高低、MA20/MA60、BOLL 轨道、已识别形态边界和未回补缺口边界作为候选价位。
3. 两个候选价位距离不超过 `0.3 × ATR14` 时合并；最终区间在候选组最小值和最大值外各增加 `0.15 × ATR14` 缓冲。ATR 不可用时价位结果整体标记不可用，不使用固定百分比替代。
4. 仅保留当前价下方最近 3 个支撑区和上方最近 3 个压力区；已经被收盘价连续两日有效穿越的区域降级或移除。
5. 区域强度为 0～100：来源多样性最高 30 分、最近 120 日有效触碰次数最高 30 分、最近验证时间最高 20 分、验证日量能确认最高 20 分。各项原始证据必须随结果保存，不能只存总分。
6. 回踩确认：价格进入支撑区后收盘未跌破下沿，回踩量能收缩，随后收盘重新站上支撑区上沿；RS 与 OBV 不得同步明显转弱。
7. 突破确认：`close > 压力区上沿 + 0.2 × ATR14`、`volume > VMA20 × 1.5`、`ADX14 > 25` 且 `RS20 > 0`；任一关键条件缺失时只显示“接近突破”，不显示“已确认”。
8. 结构失效参考线为 `支撑区下沿 - 0.3 × ATR14`；默认连续两个收盘价跌破，或单日放量跌破，才标记“结构失效”。
9. 移动保护线为 `最近有效窗口最高收盘价 - 2 × ATR14`；只作为退出观察证据，不作为自动卖出指令。
10. `观察空间比 = (下一压力区下沿 - 入场确认价) / (入场确认价 - 结构失效位)`。分母不大于 0、缺少压力区或失效位时返回 `null`；`>=2` 显示“空间较合理”，`1.5～2` 显示“空间一般”，`<1.5` 显示“上方空间有限”。

建议发送给 AI 的价位摘要：


## 6. AI 输出协议与一次/二次文案

研判成功记录必须使用结构化结果：模型内容通过本地校验后，再由本地合并可信元数据。建议保存协议如下：

```json
{
  "modelResult": {
    "verdict": "maintain|revise|new_evidence|insufficient",
    "summary": "不超过 120 字的结论摘要",
    "changes": ["相对上次结论发生的变化"],
    "evidence": ["支持本次判断的关键证据，最多 3 条"],
    "risks": ["主要风险"],
    "watchPoints": ["后续可验证的跟踪点"]
  },
  "evidenceDates": {
    "snapshotDate": "YYYY-MM-DD|null",
    "klineDate": "YYYY-MM-DD|null",
    "themeDate": "YYYY-MM-DD|null",
    "eventDate": "YYYY-MM-DD|null",
    "marketContextDate": "YYYY-MM-DD|null"
  },
  "evidenceHash": "由本地生成并回填的证据摘要哈希",
  "priceLevelSetId": "关联的本地观察价位结果 ID",
  "marketPhase": "trading|closed|non_trading",
  "isFinal": false
}
```

- `modelResult.verdict` 只能取协议中的四个枚举值；首次研判没有上次结论时，一般使用 `new_evidence` 或 `insufficient`。
- 支持 JSON Schema 的接口应启用结构化输出；不支持时仍要求返回 JSON，并由本地解析、字段校验和枚举校验。
- 校验失败时保存模型原文用于排错，但状态标记为“结果格式异常”，不得计为研判成功，也不得覆盖上次成功结论。
- `evidenceHash`、各证据日期和上次结论由本地提供并校验，不信任模型自行生成或修改。

### 6.1 首次研判输出结构

```
【研判对象】名称（代码）· 市场 · K 线截止 2026-09-04 · 快照 2026-09-04
【量价与形态】K 线结构摘要 + 指标 + 命中形态
【行业与题材】…（无数据则注明“暂无行业/题材数据”）
【大盘与主线背景】…（批量公共信息；无数据则注明“未包含市场背景”）
【事件与公告】…（无数据则注明“暂无公告事件数据”）
【综合研判】结论倾向 + 主要依据（不超过 3 条）
【主要风险】…
【后续跟踪点】…
```

### 6.2 二次研判输出结构

```
【上次结论摘要】YYYY-MM-DD 倾向：…（由本地保存的记录回填，不依赖模型记忆）
【本次数据变化】K 线新增 N 根 / 快照变化 / 题材或事件变化
【研判结论】维持 / 修正 / 新增变化 / 无法研判
【主要风险】变化后的风险提示
```

界面可将结构化结果映射为“正面观察 / 中性观察 / 风险警示 / 无法研判”，但持久化使用稳定枚举值。不得输出“买入/卖出/目标价/胜率”等词。关键证据不足时使用 `insufficient` 并说明缺失项，不以猜测补全。

## 7. 数据完整性与“二次研判”时机口径

1. K 线完整就绪：目标窗口以上市首日为起点，窗口内非合理缺日为 0，与设置页“K 线日期索引”同源。
2. K 线有限就绪：至少 60 根且日期连续，但受上市时间等客观条件影响不足目标窗口；允许研判，证据和结果必须标记“样本有限”。少于 60 根或存在非合理缺日时禁止研判。
3. 快照新鲜度：闭市后研判要求快照日期 = 最新交易日；盘中研判以实时报价为准，并在元信息标注“盘中实时”。
4. 证据日期一致性：分别保存 `snapshotDate`、`klineDate`、`themeDate`、`eventDate`、`marketContextDate`。K 线截止日期与快照日期不一致时，按钮禁用并提示“K 线截止 {d1} · 快照 {d2}，请先补齐/刷新后再研判”。
5. 证据变化检测：将标准化证据、证据日期和 prompt 版本生成 `evidenceHash`。Hash 与上次成功记录相同时，本地提示“无新增证据”，不调用模型、不新增成功记录。
6. 二次研判触发：只有 `evidenceHash` 变化后才允许二次研判。相同证据不提供强制重跑；用户需先刷新行情证据，避免重复计费和随机结果。
7. 市场阶段不得只按本机时间判断，必须同时使用上交所/深交所交易日历、北京时间、行情日期和数据源交易状态，归一化为 `trading / closed / non_trading`。
8. 盘中研判：仅由用户手工触发；只要证据 Hash 相对上次成功记录发生变化，就允许再次研判。正在执行的同一股票任务不得并发重复提交。
9. 收盘定稿：当行情源确认闭市、最终快照日期为当前交易日且日 K 已包含该交易日终值时，生成 `marketPhase=closed` 的最终证据。若当天尚无最终成功记录，允许且只允许完成一次“收盘定稿”。
10. 收盘锁定：存在相同交易日、`marketPhase=closed`、`isFinal=true` 的成功记录后，禁用当天普通研判和强制重跑；周末、节假日继续复用最近交易日的最终记录。算法版本或复权数据后来变化时可重算本地价位，但不得静默覆盖原研判记录。

## 8. 批次、幂等与结果保存

1. 批量任务开始时冻结股票清单和每只股票的证据快照；任务执行中行情刷新不改变当前批次输入。
2. 单只任务的幂等键为 `code + evidenceHash + promptVersion + model`。同一幂等键已有成功结果时直接跳过，避免停止、恢复或重复点击造成重复计费。
3. 每条任务至少保存：`batchId`、`code`、`evidenceHash`、`promptVersion`、`model`、`dataStatus`、`judgmentStatus`、`scoreStatus`、`startedAt`、`finishedAt`、`attempt`、`usage`、`durationMs`、`errorCode`。
4. `usage` 以接口真实返回为准；接口不返回时记为“未知”，不得根据字符串长度伪造精确 token 数。
5. 二次研判失败、超时或格式异常时保留上次成功结果，并将本次尝试作为独立失败记录保存。
6. 批次恢复只继续未开始、失败且允许重试的任务；已成功和相同幂等键任务不得重复调用。
7. 研判与观察价位持久化到现有本地 SQLite 数据库，不存入仅用于候选快照的 JSON 文件。研判历史采用追加记录，旧结果不可原地覆盖。
8. `judgment_records` 至少保存：`id`、`batchId`、`code`、`tradeDate`、`marketPhase`、`isFinal`、`evidenceHash`、`promptVersion`、`model`、`priceLevelSetId`、`modelResultJson`、`rawText`、`status`、`usageJson`、`durationMs`、`createdAt`。唯一约束沿用 `code + evidenceHash + promptVersion + model`。
9. `price_level_sets` 至少保存：`id`、`code`、`tradeDate`、`evidenceHash`、`algorithmVersion`、`adjustmentType`、`klineDate`、`snapshotAt`、`supportZonesJson`、`resistanceZonesJson`、`entryTriggersJson`、`invalidationLevelJson`、`exitWatchZonesJson`、`riskRewardJson`、`evidenceJson`、`createdAt`。唯一约束为 `code + evidenceHash + algorithmVersion`。
10. 观察价位先本地计算并持久化，再发起 AI 研判；AI 记录只引用 `priceLevelSetId`。再次打开详情时直接读取同证据、同算法版本的价位与研判结果，不重复计算和调用模型。
11. 当 `evidenceHash` 或 `algorithmVersion` 变化时新增价位版本；旧版本保留用于解释历史研判。数据库写入失败时不得显示“研判成功”或“收盘定稿完成”。

## 9. 文案落地前必须接线的事实（按序实施，缺一不上线）

1. 后端批量研判接口与队列：逐只调用、限速/退避、超时、失败记录、停止与续跑。
2. 研判结果落库、三类内部状态与幂等控制：冻结证据快照，保存批次号、证据 Hash、prompt 版本、模型、独立证据日期、真实 usage、耗时与错误码。
3. K 线结构化摘要模板、完整/有限/未就绪校验，以及 ATR、BOLL、ADX/DMI、RS、OBV、量能分位的本地计算与测试。
4. 支撑/压力区、入场观察条件、结构失效位、退出观察区与空间比的本地计算、证据保存和算法版本测试。
5. 指标日期对齐、前复权版本、算法版本、不可用状态和历史回放无未来数据校验。
6. 结构化输出协议、本地校验、异常原文保留，以及二次研判增量 prompt 与“上次结论 + 数据变化”回填。
7. SQLite 研判记录与价位结果表、版本追加、唯一约束、事务写入和历史读取测试。
8. 交易阶段判定、盘中手工多次研判、唯一收盘定稿、收盘锁定与非交易日复用。
9. 题材/行业归属数据接入（与 `scoring-copy-v1.md` 的题材归因共用数据源，避免重复抓取）。
10. 大盘与主线公共背景抓取（作为批次公共信息，不为每只重复请求）。
11. 事件/公告数据接入（免费源与限流策略验证后再定）。
12. 前端按钮、三类状态映射、分类进度、失败重试、无变化跳过、调用次数预估与数据日期校验文案。
13. 红涨青跌统一：AI 输出中的价格与涨跌数字若做渲染，仍遵循 `#ff4545` 红涨、`#20b7c7` 青跌，不做第三种涨跌色。

## 10. 口径红线

- 不使用“智能荐股 / 胜率 / 保证收益 / 目标价”等表述；统一为“AI 辅助研判 / 研究参考 / 不构成投资建议”。
- 数据未接线前，不得在界面写“已包含题材分析”“已综合公告消息”；缺什么如实显示“暂无 … 数据”。
- 批量任务中断或部分失败时，不显示“全部完成”；成功与失败数量必须分开展示。
- “完整就绪 / 有限就绪”只表示达到调用门槛，不表示数据完美；任何研判结果都必须标注所用证据日期与样本状态。
- 相同 `evidenceHash` 不得重复调用；盘中再次手工研判前必须先产生新的证据版本。
- 模型自由文本或结构校验失败不得标记成功，不得覆盖上次成功结论。
- 技术指标不得被解释为确定性信号；相关指标不得因数量叠加而被重复计权。
- 支撑、压力和触发标记必须来自本地可复算算法；AI 不得自行输出新的价格，也不得将观察价位表述为买卖指令。
- 盘中允许手工增量研判；当日唯一收盘定稿成功后不得重复调用模型，除非进入新的交易日。

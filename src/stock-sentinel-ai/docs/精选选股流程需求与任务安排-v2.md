# 精选选股流程需求与任务安排 v2

日期：2026-09-11  
范围：仅智诊盯盘 `src/stock-sentinel-ai/`；本地验收端口 3110。  
状态：T01～T09 已完成开发并待独立复核；T10 隔离验证已完成开发，但完整历史回放、参数定稿和发布验收因证据不足受阻。本文不代表完整流程已验收上线。

## 1. 目标与方案关系

把“扫股 → 候选池 → 盯盘”改为逐层精选、可解释、可复核的流程。允许零结果，不因数量不足放宽门槛。题材龙头作为市场强弱参照，潜力候选强调位置合理、结构改善、确认条件和风险可控。

本方案承接 `candidate-watch-selection-plan-v1.md`，与其冲突时以本文为准：默认视图从全部候选改为精选候选，但全部历史记录仍可查看；增加软数量上限和题材集中度约束；未经验证的弱市例外不直接晋级优先盯盘。既有数据量纲标准继续适用。

本次开发不包含自动交易、自动删除用户自选、自动替用户决定买入，也不以增加等待时间模拟复杂筛选。

## 2. 当前缺口与要求

| 缺口 | 新要求 |
| --- | --- |
| 扫描股票复用过旧股票快照 | 固定已选题材范围，更新范围内个股行情后筛选；不重复扫描市场题材 |
| 内存预扫描跨日不失效、刷新恢复判定不一致 | 前后端使用统一有效性结果；显示恢复与允许选股分开判断 |
| 先预筛再称板块龙头 | 全部有效成分股计算板块排名；预筛合格者另算候选排名 |

| 非空K线即算补齐成功 | 按深度、日期、缺口、复权及字段完整性验收 |

## 3. 阶段一：市场扫描与题材上下文

1. 生成市场环境、重点行业/概念、真实成分股范围与证据覆盖情况。
2. 保存批次ID、市场配置、真实交易日期、采集时间、数据源、规则版本和盘中/收盘状态。板块日期不可验证时标为未知，不能由请求日期直接赋值。
3. 题材选择综合资金、涨幅、上涨家数、涨停结构；只有名次靠前但资金/扩散证据不足时标为弱证据，不宣称强势确认。
4. 刷新只恢复已保存结果；标题按真实日期显示“当日”或“最近扫描”。设置页不显示题材条。
5. 统一交易日历与时段判断，区分集合竞价、连续交易、午休、收盘；日历缺失时明确降级。
6. 跨交易日必须重新扫描市场。同日题材过期时提示重新扫描；点击扫描股票不得隐式触发全市场扫描。

## 4. 阶段二：题材内精选初筛

### 输入和数据门槛

- 输入已确认的题材范围与当前市场配置，拉取范围内最新股票行情。
- 明确记录行情源时间、抓取时间、覆盖数及缺失股票。接口成功不等于行情新鲜。
- 排除ST、停牌、无有效价格、流动性不足及交易规则不明的标的。新股、复牌、无涨跌停限制日单独识别。
- 缺失必需字段进入“数据不足”，不得填零后正常评分。

### 防追高与双名单

- “强势观察”：涨停、明显高涨幅等标的可保留用于观察题材强度，不进入默认潜力精选。
- “潜力候选”：通过数据、流动性与初筛规则，未触发追高硬门槛；仍须候选池K线确认。
- 当天涨幅按板块实际涨跌停规则判断；涨停使用有效涨停价格和价格精度，避免简单按涨幅近似。
- 近5/10日涨幅、20日均线偏离等必须等有效K线具备后计算，不能为保持初筛速度省略最终检查。
- 低涨幅本身不加分；下跌趋势中的低价股票不得仅凭“没涨过”进入精选。
- 板块龙头排名以有效成分股为分母；成分覆盖不足标明“部分覆盖排名”。候选排名只在通过预筛者中计算。

### 数量和解释

- 每题材默认最多3只，目标2～3只；跨题材去重后默认最多20只，目标10～20只。
- 数量是上限与目标区间，不是必须选满；弱市从严，允许0只。
- 排序依次考虑策略适配、证据质量、量价改善和相对强弱；相同条件用代码稳定排序。初筛排序须标为暂定。
- 每只展示命中规则、题材归属、板块排名、候选排名、初筛理由、风险、下一步检查项。
- 展示真实漏斗：题材范围、有效行情、剔除、潜力候选、强势观察、超配额未入选。排除原因可重叠，人数总计按主原因去重。

## 5. 阶段三：候选池严格复核

### K线验收

- 默认目标250根，策略实际最小样本量由策略声明；“足够评估”和“250根已补齐”分别表示。
- 数据源返回不足目标时继续有界回退；各源结果按日期、深度、字段、复权口径评估，避免盲目拼接不同复权历史。
- 区分完整、策略可用但有限、待补齐、失败；源失败、深度不足、日期陈旧、交易日缺口分别报告。
- 上市不足250日按实际可用样本评估，不能声称补齐250日；停牌缺口依据停牌证据处理，不靠猜测豁免。
- 盘中最后一根未完成K线标记为暂定。依赖收盘确认的策略最多给“待确认”。

### 策略与风险门槛

- 复核入池时命中的策略ID和版本；规则变更后标为待重新评估，不静默替换依据。
- 第一批结构：平台首次有效突破、突破后缩量回踩、上升趋势缩量企稳。复用已有指标能力，缺失策略另列实现与回放样例。
- 检查近5/10日累计涨幅、均线偏离、异常放量长上影、趋势破坏、压力位距离及流动性。
- 入场、失效、第一目标须有可追溯价格依据，且满足失效价 < 入场价 < 目标价。风险收益比=(目标-入场)/(入场-失效)，计入可配置成本与滑点。
- 价格缺失、目标不合理或止损距离过小均不得用默认价格凑出合格比值。

### 分类与精选

| 分类 | 条件 | 默认转盯盘资格 |
| --- | --- | --- |
| 数据不足 | 必需证据缺失、陈旧或冲突 | 无 |
| 不通过 | 证据足够，但原策略或风险门槛不满足 | 无 |
| 待确认 | 结构成立但触发、量能或收盘条件未满足 | 单独人工观察入口 |
| 通过 | 原策略、数据、追高及风险收益门槛全部通过 | 有，仍需人工选择 |

通过者再按证据、风险收益、结构与题材分散性排序，默认精选最多10只，目标5～10只。超过配额标为“通过但未入精选”，不冒充不通过。全部记录保留，可筛选查看。

AI仅解释程序证据、反对理由与条件；不得覆盖数据不足或风险硬门槛。失败、不配置AI也能给出规则分类，不凭AI措辞晋级。

## 6. 阶段四：人工确认进入盯盘

1. 默认展示本批复核通过且证据有效的精选对象，建议选3～5只，默认精选转入上限5只。
2. 同一主要题材建议不超过2只；多概念股票按所有重叠归属提示集中风险，不把多个概念当成独立分散。
3. 保留手工添加和待确认观察入口，明确标为手工/观察，不冒充精选；既有自选不自动淘汰。
4. 每只保留入选理由、反对证据、触发条件、失效条件、风险收益、题材、排名、来源批次、证据时间与规则版本。
5. 行情或规则变化时标记待复核；触及失效条件时提示，不自动删除或交易。
6. 单笔和批量迁移共用逻辑：目标成功保存后才移出原池；重复转入幂等、失败可重试，保留K线和AI历史。

## 7. 参数与待验证事项

| 参数 | 初始建议 | 发布前要求 |
| --- | --- | --- |
| 每题材/扫股总上限 | 3 / 20 | 可配置；不凑数 |
| 候选池精选/本批精选转盯盘上限 | 10 / 5 | 不限制用户历史自选总数 |
| 同主要题材精选盯盘提示线 | 2 | 检查跨概念重复暴露 |
| 当天涨幅防追高 | 按板块分别配置 | 结合涨跌停制度回放后定数值 |
| 5/10日涨幅、均线偏离、流动性 | 待回放确定 | 不把未经验证阈值当收益保证 |
| 最低风险收益比 | 2作为回放起点 | 校验价位算法、成本敏感性后定稿 |
| 行情新鲜度、题材有效期 | 分交易时段配置 | 源无时间或超限时降级；禁止无限复用 |

回放使用有真实日期、当时可得的证据，禁止用未来数据选题材或确认形态。记录样本区间、样本量、缺失覆盖、入选数量、过热过滤率、后续最大不利/有利波动；数据不足时标记未验证，不输出虚假胜率。手工观察不受实验参数自动清理。

## 9. 按任务难度安排开发模型

以下是本项目的工程分工建议，不是官方性能排名。实际可用性以运行环境为准。本节仅安排后续工作，不自动切换模型或启动并行代理。

| 模型 | 适用任务 | 使用边界 |
| --- | --- | --- |
| DeepSeek V4.1 Flash | 边界明确的字段映射、兼容迁移、元数据贯穿和隔离单测 | 中高风险跨模块结果必须由Sol复核，不独立决定复权/收盘语义或任务验收 |
| GPT-5.6 Terra | 边界明确的页面、字段保存、接口接入、分类展示和缺陷修复 | 核心筛选与跨模块一致性不以单次开发结果直接验收 |
| GPT-5.6 Sol | 主要开发、跨文件修改、数据校验、队列与迁移、业务回归 | 关键数据与筛选语义须独立复核 |
| GPT-6 Astra | 复杂契约、精选规则、防追高、风险收益、并发一致性和最终审查 | 同样必须提交可运行测试与证据，不能替代历史回放 |

复核应以需求、实际代码差异和测试证据为输入，不能只阅读开发者摘要。由Astra开发的核心任务，也必须经过独立测试执行；最终修订复核不等于外部独立策略验证。

### 执行与交接要求

1. 默认逐任务推进，遵守T01～T10依赖顺序；每次只实现有明确验收条件的范围，不一次性改完整条链路。
2. 每项交付记录：任务编号、实际改动文件、业务行为、测试样例和结果、兼容影响、未解决风险及下一步。建议记录在目标子项目的任务验收文档中。
3. 任务状态使用“待办 → 开发中 → 待复核 → 已验收”；测试失败或必需证据缺失时保持未验收。开发模型不得只凭构建成功把业务任务标为完成。
4. 优先验证实际业务断言，例如过热股票被分流、数据不足不能晋级、添加成功后页面正确刷新、重复迁移不丢数据。语法检查和构建只是基础检查。
5. 审查发现问题后交回对应任务修复，再运行受影响检查；通过后才解锁依赖任务。无法取得历史数据时明确标记回放未完成，不虚构结果。
6. 只使用一个模型时，建议Sol承担全程开发；质量优先且预算允许时使用Astra。Terra适合边界明确的子任务，核心任务保留独立复核环节。
7. 若建议模型不可用，记录实际使用模型与尚未完成的复核项，不声称已经获得另一模型审查。模型切换不改变需求和验收门槛。

## 10. 回归与交付清单

- 场景：市场弱、无强势题材、接口部分失败、涨停龙头未过量能门槛、低涨幅但累计大涨、多个题材重复股票、少于配额、零结果。

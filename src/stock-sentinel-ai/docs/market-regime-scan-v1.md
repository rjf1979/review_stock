# 市场环境驱动的全市扫描方案 v1

> 日期：2026-09-05  
> 范围：定义智诊盯盘全市扫描的决策顺序、市场环境分类、题材筛选、形态匹配和候选池准入证据。  
> 状态：v1 已接入实时全市场快照、腾讯指数、东方财富板块资金与成分股范围，以及涨停、跌停、炸板、封板率和连板梯队。历史回放阈值校准仍待实施。

## 1. 结论

全市扫描采用三级漏斗：先判断市场环境，再筛选有资金和扩散证据的重点题材或行业，最后只在这些板块成分股中运行与当前环境匹配的形态规则。

```text
市场环境判断
  -> 重点题材 / 行业筛选
  -> 板块成分股扫描
  -> 环境适配形态复核
  -> 量价与风险检查
  -> 候选池
```

形态命中只是个股技术证据，不单独构成优先候选或操作结论。题材资金也只能确认板块环境，不能替代个股量价和风险检查。

## 2. 市场环境

市场环境由指数趋势、市场宽度、两市成交额变化、涨跌停数量、炸板或高位回落比例共同判断。输出一个主状态，并记录计算时间与原始证据日期。

| 环境 | 识别重点 | 扫描策略 |
| --- | --- | --- |
| 强势主升 | 指数趋势向上，成交额放大，市场宽度改善，涨停扩散 | 关注趋势延续和突破，允许较少的主线板块进入扫描 |
| 震荡偏强 | 指数区间运行但重心抬高，结构性资金活跃 | 关注回踩确认、均线结构和首次启动 |
| 轮动震荡 | 指数缺少方向，题材切换快，板块强度分化 | 优先识别前排题材与低位启动，缩短题材有效期 |
| 恐慌修复 | 前期弱势后止跌，宽度和量能开始恢复 | 只观察反包、二次探底、关键均线收复等确认信号 |
| 弱势退潮 | 指数走弱，成交额萎缩，炸板或高位回落扩大 | 收缩候选池，默认观察；无确认信号不进入优先候选 |

市场环境不明确或数据不足时，扫描回退为全市快照预筛，但提高量能门槛、减少候选数量，并明确标记“环境未确认”。

涨跌停情绪结构直接参与状态判断：跌停扩散、封板率低或梯队断层时压制突破策略；涨停扩散、封板率较高且二板以上梯队完整时，才确认强势主升。三类池任一不完整时置信度不得标为“证据完整”。

## 3. 重点题材与行业

在市场环境允许时，按题材或行业选择重点扫描范围。单个题材至少应评估以下证据：

1. 当日及近期涨幅、资金净流入和成交额变化。
2. 板块上涨家数、涨停数量与强势股数量，确认强度是否扩散。
3. 龙头、前排和中军是否共同走强，避免由单只股票拉升造成的假强势。
4. 强度持续性；轮动环境可接受更短周期，但应降低确定性。
5. 数据日期与完整性；缺失时题材状态为“不可用”，不以零分或主观判断代替。

默认保留排名靠前的 3 至 8 个题材或行业。市场轮动加快时可增加数量，但应降低每个题材的优先级；弱势退潮时可以不选题材。

## 4. 形态匹配

全市扫描只启用与当前市场环境匹配的形态。具体阈值、窗口和形态计算仍以 `screener-core` 规则为准。

| 环境 | 优先形态 | 降低权重或不作为优先候选 |
| --- | --- | --- |
| 强势主升 | 放量突破、平台突破、箱体突破、上升三角形、N 字突破、强势横盘突破 | 地量地价、无板块支持的弱势反弹 |
| 震荡偏强 | 缩量回踩 MA20、均线多头、均线金叉、涨停后缩量回踩、二次启动 | 连续大阳后的追涨型突破 |
| 轮动震荡 | 首次放量启动、均线金叉、阳包阴、低位平台突破 | 无题材扩散支持的孤立形态 |
| 恐慌修复 | 假跌破反包、长下影企稳、双底、二次探底、关键均线收复 | 仅因超跌或 RSI 低位的单一信号 |
| 弱势退潮 | 地量企稳、缩量抗跌，仅作观察 | 高位放量、加速突破、连续涨停后的追涨 |

## 5. 候选池准入

候选股票应保存完整入选路径，供详情页、人工复核和 AI 研判使用：

```text
市场状态：震荡偏强
题材依据：板块资金第 2、上涨率 71%、涨停 2 只
形态依据：缩量回踩 MA20
个股依据：量比、换手、成交额、主力净流入
风险标记：接近压力位 / 涨幅透支 / 板块后排
```

进入优先候选池至少需要：

- 市场环境与形态策略匹配；
- 所属题材或行业具备有效资金或扩散证据；
- 个股命中当前环境适配形态，并有量价确认；
- 通过流动性、位置、涨幅透支与资金背离检查。

市场退潮、题材未扩散、形态没有量能确认、单日涨幅明显透支，或价格与主力资金显著背离时，不得仅因形态高分列为优先候选。

## 6. 产品分层

| 列表 | 作用 | 最低条件 |
| --- | --- | --- |
| 观察题材池 | 展示当前具备环境和资金证据的题材或行业 | 市场允许，题材数据有效 |
| 技术候选池 | 展示重点板块内命中适配形态的股票 | 题材有效，形态与环境匹配 |
| 优先候选池 | 排列需要人工优先复核的股票 | 量价、流动性、位置和风险检查通过 |

当前候选池属于“技术候选池”：它保存市场环境、板块范围、形态预筛、量能和风险标记；进入后仍须补齐 K 线并进行形态复核，不能表述为自动买卖结论。

## 7. 快照存储与数据质量

实时全市场快照同时保留兼容 JSON 文件，并按市场归档到 SQLite：

- `market_snapshot_batches`：一条记录对应一个交易日、一个市场、一次完整分页抓取，保存来源、抓取时间、接口总数、实际数量、完整性和错误原因。
- `market_snapshot_records`：以 `(batchId, code)` 为主键保存归一化行情字段；按交易日/市场和证券代码建索引。
- 写入使用单事务批量插入，完成后只导出一次 `sql.js` 数据库，避免数千行快照逐条刷盘。
- 全市场有效股票少于 1,000 时拒绝计算广度；不完整批次只保留诊断信息，不能作为完整市场判断依据。
- 默认保留每个市场最近 45 个交易日的完整批次；历史回放需求另行延长归档策略。

## 8. 实施顺序

1. 定义并持久化市场环境契约：指标、状态、证据日期、缺失原因和回退策略。
2. 接入题材或行业强度、资金、扩散和成分股数据，确定缓存与日期校验规则。
3. 在扫描接口中先生成市场环境和重点题材范围，再限制股票快照请求与 K 线复核范围。
4. 为每个市场环境建立启用、降低权重和禁用的规则集合。
5. 扩展候选池记录，保存市场、题材、形态、量价和风险证据。
6. 改造全市扫描页面，按“环境 -> 主线 -> 个股候选”展示过程与数据缺失状态。
7. 用历史交易日回放校验候选数量、题材覆盖、形态命中和人工复核保留率，再调整阈值。

# 智诊盯盘 · 历史分时数据集与采集说明

> 范围：`E:\tdx_data`（历史分时，2021-01-01 ~ 2022-12-31）。本文是**已实现**的记录。
> 日期：2026-09-21。实现：`tools/collect_tdx_timeshare.py`（采集）、`tools/tdx_timeshare.py`（格式与自检）、
> `test/test_tdx_timeshare.py`（12 项守门测试）。

## 1. 为什么要自采

| 来源 | 起点 | 卡点 |
| --- | --- | --- |
| 通达信客户端「盘后数据下载」 | 最近约 **100 天** | 到不了 2021 |
| datatool 四代分笔包 | **2024-01-04** | 转档只有 GUI 会做；自研需逆向 `.htc`（每股独立 zlib + 变长差分） |
| **行情服务器历史分时/分笔** | **2020-01-02** | 需自写采集器（无现成转档依赖） |

因此长历史只能自采。本阶段只采**分时**（每分钟 close + volume），按 (股票 × 交易日) 一次请求。

## 2. 格式契约

独立后缀 `.fs` + 独立 16 字节记录，**不复用 `.lc1`**：分时没有 OHLC，写成 `.lc1` 会让下游当分钟 K 线用。

```
<u32 date> <u16 time> <i16 reserved> <i32 price_cent> <u32 volume>      // 16 字节，小端
```

| 字段 | 含义 |
| --- | --- |
| `date` | YYYYMMDD |
| `time` | HHMM，该分钟**结束**时刻；隐含固定网格 `0931..1130 + 1301..1500` 共 **240 槽**（接口不返回时间字段） |
| `price_cent` | 价格 × 100（整数「分」）。A 股最小变动 0.01 元，实测分时价格全在 0.01 网格上 |
| `volume` | 该分钟成交量，单位 **手**（×100 = 股） |
| `reserved` | 固定 0 |

价格**未复权**。**没有 open/high/low/amount**，需要分钟内极值必须另采分笔。

```
E:\tdx_data\
  meta.json                 字段契约、窗口、来源、参数
  calendar.txt              交易日清单（服务器探测所得）
  fs\<sh|sz>\<market><code>.fs
  state\days.json           逐日完成状态（断点续爬）
  state\calendar.json       日历探测覆盖的区间（防止换窗口时静默用窄日历）
  state\gaps.json           未能取到的 (代码, 日期)
  logs\collect-*.log
  report\coverage-*.json
```

## 3. 采集方式

```powershell
# 正式采集（默认 sh-main + sz-main + chinext，不含科创板与北交所）
python tools/collect_tdx_timeshare.py --start 20210101 --end 20221231 --workers 12 --allow-partial-day

# 断点续爬：直接重跑同一条命令，已完成的交易日会跳过
# 回补 gaps.json 里的缺口并重建受影响文件
python tools/collect_tdx_timeshare.py --repair

# 只读自检
python tools/tdx_timeshare.py info
python tools/tdx_timeshare.py verify [--code 600519] [--limit 200]
python tools/tdx_timeshare.py day --code 600519 --date 20210104
```

板块由 `--boards` 显式声明：`sh-main`(60) / `sh-star`(68) / `sz-main`(000,001,002,003,004) /
`chinext`(300,301) / `bj`(43,83,87,92)。默认不含科创板与北交所。

可靠性：启动时对候选服务器做健康检查，每线程独占一条连接；拿不到的 (代码, 日期) 记进
`gaps.json`，**绝不冒充停牌**；单只文件内按日期升序追加，`--repair` 回补后重建。

## 4. 实测（2026-09-21）

| 项 | 实测值 |
| --- | --- |
| 交易日历 | 工作日 521 个 → **交易日 485 个**（2021 年 243 + 2022 年 242，与公开口径一致） |
| 股票池 | **4606 只**（sh-main 1702 + sz-main 1495 + chinext 1406 + 4 个指数） |
| 请求量 | 4606 × 485 ≈ **223 万次** |
| 吞吐 | **428 请求/秒**（12 线程），0 错误 0 重试 |
| 单日耗时 | ≈ 11 秒（4606 次请求 + 3727 次追加落盘） |
| 预计总耗时 | ≈ **1.6 小时** |
| 落盘体积 | ≈ 4600 只 × 485 天 × 240 槽 × 16 B ≈ **8.6 GB** |
| 对账 | 末槽（15:00）价 == 本地 `.day` 收盘价：试跑 A 200 只次、试跑 B 879 只次、实测采样 **全部一致** |

## 5. 采集过程中查实的三件事（都会影响别的判断）

1. **本机 `D:\new_tdx\vipdoc\*\lday\*.day` 的日线有大段缺口**（按日期并集实测）：
   2000–2011 完整、**2012–2020 整段没有**、2021 只有 103 天（缺 1–7 月）、2022 起完整。
   **后果**：不能拿它当交易日历（会静默漏采半年），也不能拿它给缺口期做收盘价对账——
   采集器已改成向服务器逐日探测日历，并把缺口显式打进日志。
   注意这是**客户端那份**的问题：项目自己的日线库 `data/hsjday` 是完整的
   （1990-12-19 ~ 2026-09-18，逐年交易日数与官方一致），回测用的是后者。
2. **北交所 43/83/87 段用历史分时接口取不到**（`market=2` 对 `430047`/`831010`/`873169` 全返回 0 点，
   而 `920002` 正常）。所以默认板块不含 `bj`，要采必须先单独核实。
3. **客户端「盘后数据下载」的分钟数据只到最近约 100 天**，所以「客户端下载 + 项目直读」这条路
   解决不了 2021~2022 的窗口。

## 6. 覆盖口径与边界

* 每 (股票, 交易日) 只有两种结果：**240 槽** 或 **0 槽**（停牌/未上市）。没有中间态，
  实测 521 个工作日探测只有 `{0, 240}` 两种点数。
* 「无数据」合法性已按**已采集交易日**审计：876/877 只在本机 `.day` 里同样无成交记录
  （= 当时未上市/停牌），**异常 0 只**；余 1 只 `sz001246` 本机无 `.day`，待人工看。
* 2021 上半年这 140 天**没有本地参照**，只有结构校验（240 槽 + 0.01 网格），没有独立源对账。
* 本数据集**不含 OHLC**。需要「次日早盘最高价」这类分钟内极值的口径，要走分笔路线
  （服务器分笔同样从 2020-01-02 起，实测 open/close 逐根精确、high/low 有 0.4%~5.8% 的根偏差）。

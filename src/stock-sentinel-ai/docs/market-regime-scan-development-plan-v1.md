# 市场环境驱动扫描 · 需求开发计划 v1

> 日期：2026-09-05  
> 关联方案：`market-regime-scan-v1.md`  
> 目标：将现有“全市快照规则预筛”逐步升级为“市场环境 -> 重点题材 -> 板块成分股 -> 适配形态 -> 候选池”的可核验扫描流程。

## 1. 当前基线与范围

当前扫描接口以东方财富全市场快照为输入，按照市场范围、量能评分和启用规则预筛，结果进入候选池后再补齐 K 线并复核形态。当前页面不能声称已完成市场环境判断、题材资金确认或板块成分股扫描。

本计划只改造智诊盯盘的扫描、候选池和相关本地数据契约，不改动其他桌面产品，不提供自动交易、买卖指令或收益判断。

## 2. 需求清单

| 编号 | 需求 | 结果 |
| --- | --- | --- |
| R1 | 生成市场环境 | 输出五类环境、证据、数据日期、置信状态与回退原因 |
| R2 | 识别重点题材或行业 | 按资金、涨幅、扩散、持续性选出有限主线 |
| R3 | 取得板块成分股 | 将扫描范围收缩到重点板块成分股，并保留来源与日期 |
| R4 | 动态选择形态 | 按市场环境启用、降权或禁用形态规则 |
| R5 | 统一候选证据 | 保存环境、题材、形态、量价和风险路径 |
| R6 | 改造扫描页面 | 清晰显示环境、主线、回退与扫描结果，不误导为投资结论 |
| R7 | 支持回放验证 | 用历史交易日检查数据完整性、候选规模和规则效果 |

## 3. 阶段计划

### 阶段 A：数据契约与市场环境引擎

交付：新增 `market-regime.js`，以纯函数输出可测试的市场环境结果；新增本地快照存储或扩展现有快照元数据。

输入：主要指数趋势、全市场涨跌比例、成交额及变化、涨停/跌停、炸板或高位回落指标。每项必须携带数据日期、抓取时间和来源。

输出契约示例：

```json
{
  "status": "range_strong",
  "label": "震荡偏强",
  "confidence": "confirmed",
  "asOf": "2026-09-05",
  "evidence": {
    "breadth": { "upRatio": 0.61, "available": true },
    "turnover": { "amountYi": 12345, "changePct": 8.2, "available": true },
    "limitStructure": { "upLimit": 58, "downLimit": 3, "openBoard": 12, "available": true },
    "indices": []
  },
  "fallback": null
}
```

缺失关键指标时，`confidence` 必须为 `partial` 或 `unavailable`，并返回可读原因。不得用当前数据伪造历史状态。

验收：同一输入必得同一输出；五类环境、临界值、缺失回退均有单元测试；返回数据可追溯至日期和来源。

### 阶段 B：题材强度与板块成分股

交付：新增题材强度服务和板块成分股服务，优先复用现有 `theme.js` 的板块归属能力；新增当日缓存和失效规则。

题材强度至少包含：涨幅、资金净流入、成交额、上涨家数比例、涨停或强势股票数量、连续观察周期。输出 `available`、`asOf`、`fetchedAt` 与缺失原因。

重点题材选择规则：

- 强势主升与震荡偏强默认取前 3 至 5 个；
- 轮动震荡可取前 5 至 8 个，降低每个题材优先级；
- 恐慌修复只保留有修复证据的题材；
- 弱势退潮可以返回空题材池；
- 数据不完整时不把题材评分写成 0，不产生“已确认主线”状态。

验收：同一交易日重复读取命中缓存；题材和成分股数据能各自标出日期与来源；空数据、接口限流和部分失败均能降级。

### 阶段 C：扫描漏斗与规则策略

交付：扩展 `screener-core`，将扫描拆为环境、题材范围、快照预筛、K 线复核和风险检查五步；保留现有全市扫描作为回退路径。

新增策略映射：

```text
市场环境 -> 优先规则 ID / 降权规则 ID / 禁用规则 ID / 量能门槛 / 候选数量上限
```

扫描返回新增字段：

```json
{
  "marketRegime": {},
  "focusThemes": [],
  "scanScope": { "mode": "theme_constituents|all_market_fallback", "stockCount": 0 },
  "strategy": { "enabledRuleIds": [], "deprioritizedRuleIds": [] },
  "candidates": []
}
```

风险检查首版仅使用可复算数据：单日涨幅透支、量价不确认、主力资金与价格背离、接近关键压力位、板块后排。风险字段必须写明触发原因，不得由模型生成。

验收：主线范围下的扫描股票数小于全市场范围；环境不可用时回退逻辑可解释；所有候选均可追溯到环境、题材、形态和量价证据。

### 阶段 D：候选池数据迁移与排序

交付：扩展候选池记录，兼容现有 `candidate-pool.json`，不清空用户候选。

建议新增字段：

```json
{
  "marketRegime": { "status": "", "asOf": "", "confidence": "" },
  "themeEvidence": [{ "name": "", "rank": 0, "asOf": "", "score": null }],
  "scanScope": "theme_constituents",
  "strategyRuleIds": [],
  "riskFlags": [],
  "selectionTrace": []
}
```

旧记录缺失新增字段时显示“历史候选，未按环境策略生成”，不得补造环境或题材证据。候选池排序先保持现有量能分，三维评分只在 `scoring-copy-v1.md` 的前提全部满足后单独上线。

验收：旧候选可正常读取、删除、转自选和打开详情；新旧记录展示清晰区分；字段持久化后重启不丢失。

### 阶段 E：全市扫描页面改造

交付：改造“选股扫描”页面，按顺序呈现市场环境、重点题材、扫描范围、策略形态和候选结果。

页面状态：

- 加载：依次显示“判断市场环境”“筛选重点题材”“扫描成分股”“复核候选”。
- 成功：显示环境标签、证据日期、重点题材数量、扫描范围和结果数量。
- 部分数据：显示已使用的回退范围与缺失原因。
- 空结果：区分“无有效主线”“主线内无形态候选”“数据未就绪”。
- 错误：保留上次成功结果，不把错误显示为零值或空主线。

候选列表增加“入选路径”入口或详情摘要，显示环境、题材、形态和风险标签；在 375、768、1024、1440px 下保持可扫描和无页面横向溢出。

验收：键盘可操作；加载、空、部分、错误和 reduced-motion 状态完整；列表不重复展示同一证据；页面文案不暗示买卖建议。

### 阶段 F：历史回放、阈值校验与发布

交付：增加离线回放脚本或测试夹具，针对至少 20 个交易日重放市场环境、重点题材和候选池结果。

核验指标：

- 市场环境数据完整率与回退比例；
- 每日重点题材数量、扫描范围和候选数量；
- 候选的题材覆盖率、形态命中率和风险标记覆盖率；
- 与人工复核结果对照的保留率；
- 接口限流、缓存命中和运行耗时。

阈值采用配置化版本保存。调整阈值后必须重新回放，不能仅因单日行情修改。

验收：单元、契约和前端测试通过；真实数据日期校验通过；桌面和移动视图完成视觉检查；文案与实际接线能力一致。

## 4. 开发顺序与依赖

```text
阶段 A：市场环境契约
  -> 阶段 B：题材与成分股数据
     -> 阶段 C：扫描漏斗与形态策略
        -> 阶段 D：候选池迁移
           -> 阶段 E：扫描页面
              -> 阶段 F：回放与阈值校验
```

阶段 A 和 B 未完成前，不改写生产扫描结果的含义。阶段 C 和 D 完成后才接入页面；阶段 E 完成后再进行回放和阈值调整。

## 5. 模块影响

| 模块 | 预计改动 |
| --- | --- |
| `data.js` | 市场指标、题材强度和板块成分股数据获取、日期校验、缓存入口 |
| `market-regime.js` | 新增：环境分类、证据标准化和回退策略 |
| `theme.js` | 复用或扩展：题材归因、题材强度与成分股缓存 |
| `screener-core.js` | 扫描漏斗、环境策略映射、风险检查和结果契约 |
| `candidate-pool.js` | 新增证据字段及旧记录兼容 |
| `server.js` | 新增或扩展扫描、环境、题材接口 |
| `frontend/index.html` | 扫描流程界面、状态反馈、候选入选路径与响应式布局 |
| `test/` | 环境分类、题材降级、扫描契约、候选迁移和前端状态测试 |

## 6. 交付拆分

第一期交付阶段 A 和 C 的全市场回退模式：即使题材数据暂不可用，也能先根据市场环境选择形态策略，并明确显示“未启用题材范围收缩”。

第二期交付阶段 B、C 和 D 的完整数据链路：重点题材和板块成分股实际参与扫描，候选池保存入选路径。

第三期交付阶段 E 和 F：完成页面改造、历史回放、阈值定稿和发布验收。

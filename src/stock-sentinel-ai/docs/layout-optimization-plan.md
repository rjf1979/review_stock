# 智诊盯盘布局优化评审与工作安排

> 状态：阶段 1、阶段 2 已实施；阶段 3 已完成颜色收束、窄屏关键列和候选排序（列管理、密度切换待评估）；阶段 4 已完成焦点管理与自动化契约校验，待进行真实桌面端多尺寸视觉回归。  
> 评审日期：2026-09-04  
> 范围：`frontend/index.html` 的桌面端与移动端信息架构、布局和交互状态；不改变行情数据契约、扫描规则或 AI 接口协议。

## 结论

现有版本的视觉基础已达到可用水平：深浅主题、红涨绿跌语义、表格固定表头、K 线详情、加载/空/错误状态和键盘焦点都已具备。下一阶段不应继续叠加页面或装饰，而应将界面改成围绕“**发现 -> 入池 -> 研判 -> 盯盘**”的单一工作流。

当前最高优先级是重构信息架构，而不是更换色彩或大幅重绘图表。建议保留现有克制、高密度的金融工作台风格，去除不必要的悬浮感、渐变按钮与卡片层级，让数据、任务状态和下一步操作成为视觉主角。

## 颜色参考（2026-09-04）

用户提供的参考图确认为**报价列表与涨跌语义**的视觉基准，而非完整页面布局模板。它的有效特征是深石墨背景、低对比细分隔线、白灰名称/代码，以及用高饱和红和青蓝承担唯一的涨跌强调。数值优先于辅助标签，因此适合诊股和实时盯盘的高频扫读。

| 语义 token | 建议值 | 使用边界 |
| --- | --- | --- |
| `--bg` | `#1c1c1c` | 应用底色；避免纯黑造成文字边缘过硬 |
| `--surface` | `#262626` | 列表与详情容器；不再依赖渐变营造层次 |
| `--border` | `#363636` | 行分隔、表头和弱边线；不用于主要强调 |
| `--text` | `#eeeeee` | 股票名称、关键标签和主要正文 |
| `--text-muted` | `#9b9b9b` | 代码、时间、次要字段和空状态说明 |
| `--up` | `#ff4545` | 最新价、涨跌幅、正向主力资金、上涨 K 线；只表达上涨，不作为通用主色 |
| `--down` | `#20b7c7` | 最新价、涨跌幅、负向主力资金、下跌 K 线；替换当前的绿色下跌语义 |
| `--market-badge` | `#b88620` | 创业板/市场标识等辅助标签；面积受控，不与涨跌色竞争 |
| `--accent` | `#8f9aa3` | 非行情交互焦点、选中态与可操作控件；不可与涨跌色混用 |

实施准则：

- 涨跌颜色只服务于行情方向，不用于“保存、扫描、成功、警告”等通用交互状态。
- 价格、涨跌幅、主力资金三列使用同一方向色；名称和代码始终保持中性，避免整行染色。
- 表格不使用隔行填充和大面积卡片阴影，优先使用 1px 分隔线、固定列和数字对齐建立秩序。
- 深色主题优先作为桌面端默认主题；浅色主题保留为可选模式，并确保红/青在两种背景上都满足可读性要求。
- 按钮使用中性实体色或描边，主操作仅使用非行情的交互色；不使用蓝色渐变和悬浮位移作为强调。

## 发现与建议

| 优先级 | 问题 | 对日常盯盘的影响 | 优化方向 |
| --- | --- | --- | --- |
| P0 | 高频工作流被拆为 3 个平级页面：扫描、候选池、自选盯盘 | 用户需要反复切页，无法判断候选是否已经研判、是否已转入盯盘 | 建立“工作台”主视图，候选池为核心列表；扫描作为候选来源，自选作为关注状态而非独立主流程 |
| P0 | 扫描结果同时给出“纳入候选池”和“加入自选”，但没有下一步状态 | 用户无法一眼看出处理进度，容易重复操作 | 每只股票统一状态：`新候选 / 待研判 / 已研判 / 盯盘中`；行操作只保留下一步主操作，其余放入更多菜单 |
| P0 | AI 入口仅在 K 线详情底部，结果是长文本 | AI 研判无法与关键证据并列比较，也难以回看或形成行动状态 | 详情改为两栏：左侧 K 线，右侧“研判摘要 + 证据 + 风险 + 关注条件”；保留原文折叠展开，并将研判时间、数据截止日和模型标识固定展示 |
| P1 | 顶部数据状态只显示 K 线库、快照和自选数量 | 数据是否可用于当前扫描、候选池和 AI 研判并不直观 | 顶部改为紧凑“数据健康条”：快照日期、K 线覆盖率、刷新状态、待处理候选数；异常使用单一可操作告警 |
| P1 | 设置页混合日常操作、后台维护、敏感 AI 配置和规则编辑 | 高频用户会看到低频运维内容；配置风险和认知负担偏高 | 分为“工作台偏好”“数据维护”“AI 连接”“规则库”四个折叠区；默认仅展开当前异常或最近使用的区块 |
| P1 | 大量胶囊按钮、阴影与渐变同时出现 | 界面接近通用 SaaS 控件语言，金融数据的信号层级被削弱 | 保留一个主按钮和一个浅色选中态；筛选 Chip 使用低圆角矩形；减少阴影、移除非必要的 hover 位移 |
| P1 | 移动端将 4 个模式按钮平均压缩在同一行 | 375px 下文字、触控区和状态徽标争夺空间 | 移动端改为底部三项主导航（工作台、扫描、设置），“候选/自选”归入工作台分段；桌面维持侧栏或顶部导航 |
| P2 | 表格列较多，且操作列有两个文字按钮 | 横向阅读和行扫描成本高，特别是候选池/自选表之间切换时 | 固定代码、名称、涨跌幅和状态；把低频字段放列管理或详情；操作改为图标按钮并提供 tooltip/无障碍名称 |
| P2 | 详情弹框没有显式的焦点捕获、关闭后焦点回归和数据刷新提示 | 键盘用户可离开弹框；行情变化时不易判断结果是否过期 | 实现 modal focus trap、关闭后回到触发行；在详情展示“行情时间 / K 线日期 / 研判时间”与一键刷新 |

## 目标布局

### 桌面端（1024px 及以上）

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 智诊盯盘   [工作台] [扫描] [设置]       数据健康 | 刷新 | 用户状态 │
├──────────────┬──────────────────────────────┬────────────────────────┤
│ 关注清单     │ 候选与盯盘主列表             │ 个股研判抽屉           │
│ - 待研判     │ 筛选 / 排序 / 批量操作       │ 名称、价格、涨跌       │
│ - 已研判     │ 代码 名称 状态 信号 涨跌 风险│ K 线 / AI 摘要         │
│ - 盯盘中     │                              │ 证据、风险、关注条件   │
│ 数据异常     │                              │ 加入/移出盯盘          │
└──────────────┴──────────────────────────────┴────────────────────────┘
```

- 工作台是默认入口，主列表默认显示候选池并可切换“全部 / 待研判 / 盯盘中”。
- 扫描页只负责配置市场和触发扫描；结果可批量“纳入候选”，扫描完成后跳转工作台并显示新增数量。
- 选中股票在右侧抽屉中打开；只有需要更大图表或比对时才使用全屏详情弹框。
- 设置从主工作区隔离；数据不完整时用健康条直接跳转对应维护区。

### 移动端（375px 至 767px）

- 顶部仅保留品牌、数据异常提示和刷新入口。
- 底部导航为“工作台 / 扫描 / 设置”；工作台内用分段控件切换“候选 / 盯盘”。
- 主列表采用两行信息密度：第一行“名称、代码、涨跌、状态”，第二行“信号、量比、成交额、最近研判”。
- 个股详情使用全屏页面或底部抽屉，K 线先于 AI 文本；AI 摘要默认展开，完整原文按需展开。

验收：基线截图、流程清单和状态数据样例进入测试资产；不修改生产布局。

### 阶段 1：信息架构与候选状态（2 到 3 天）

1. 将导航收敛为“工作台 / 扫描 / 设置”，实现工作台内的候选与盯盘分段视图。
2. 为候选池增加 `新候选、待研判、已研判、盯盘中` 状态和批量转移操作。
3. 统一扫描、候选池和自选列表的行模型、状态徽标和主操作。
4. 将数据完整性提示合并到顶部数据健康条，并提供准确跳转。

验收：从扫描命中到进入盯盘不超过 3 次明确操作；任何股票在各列表中只显示一个一致状态；桌面和移动端无横向页面溢出。

### 阶段 2：个股研判工作面（2 到 3 天）

1. 将详情调整为桌面抽屉/双栏和移动端全屏详情。
2. 建立 AI 研判结构化展示：结论、证据、风险、关注条件、数据时间、模型与原文。
3. 增加详情内的“刷新行情”“加入盯盘”“更新研判”动作，并显示各自 loading、success、error 状态。
4. 实现弹框焦点捕获、关闭后回归触发元素和 ESC 关闭。

验收：用户可在同一视面看见价格、K 线、形态证据和 AI 摘要；AI 失败、未配置、数据过期均有可执行提示；键盘能完整完成打开、研判、关闭。

### 阶段 3：视觉收束与表格效率（1 到 2 天）

1. 收敛按钮层级：每个区域最多一个主操作，低频操作改图标按钮并配 tooltip。
2. 按“颜色参考”统一行情红涨青跌、深石墨表面和中性控件；减少渐变、阴影、胶囊控件与 hover 位移，建立统一的金融工作台 token。
3. 为表格加入固定关键列、可选列、排序与紧凑/舒适密度切换。
4. 完成 375、768、1024、1440px、200% 文本缩放、深浅主题和 `prefers-reduced-motion` 的视觉回归。

验收：主要列表在 1024px 可读取关键列；375px 不出现内容遮挡；正文对比度至少 4.5:1；涨跌方向在报价、资金和 K 线中始终遵循红涨青跌；所有图标操作有可访问名称与键盘焦点。

### 阶段 4：质量验证与上线准备（1 天）

1. 补充状态与交互测试：扫描、批量入池、状态流转、AI 成功/失败、数据不完整、刷新轮询和焦点管理。已补充弹框焦点陷阱、初始焦点、Esc 关闭和触发元素焦点恢复的前端契约校验。
2. 对核心路径做手动验收：首次使用、日常盘中盯盘、收盘后复盘、无网络和 AI 未配置。
3. 更新 README 的界面说明和截图，记录数据与 AI 使用边界。

验收：既有 `npm run check` 与全部单测通过；新增 UI 状态测试通过；完成 375、768、1024、1440px、200% 文本缩放和减弱动效的真实页面回归，确认无 P0/P1 布局缺陷后再构建桌面版。

## 交付顺序与风险控制

1. 先实现阶段 1 的信息架构和状态模型，再实施详情与视觉调整。不可先换皮，否则会固化当前割裂的工作流。
2. 候选状态和 AI 研判记录可能涉及本地存储迁移；必须兼容已有 `watchlist`、候选池和 K 线缓存，不能因改版清空用户数据。
3. AI 结果须带数据时间与模型标识，且继续保留“仅作研究参考，不构成投资建议”的边界。
4. 不扩大到云同步、自动交易、外部榜单或新的行情数据源；这些不属于本次布局优化范围。

## 本轮不实施项

- 不改变后端行情接口、K 线数据契约与筛选算法。
- 不引入新的 UI 框架、图标库或第三方埋点。
- 不新增 AI 模型供应商或修改 API Key 存储方式。
- 不发布桌面安装包；待上述布局优化和验收完成后再进入完整发布链路。

# 智诊盯盘 · 本地通达信（TDX）数据源接入说明

> 范围：`src/stock-sentinel-ai/` 的 K 线多源链。本文是**已实现**的记录，不是提案。
> 日期：2026-09-19。守门测试：`test/tdx-source.test.js`、`test/kline-source-contract.test.js`、`test/screener-core.test.js`

## 1. 要解决的问题

腾讯 `fqkline` 对部分证券（688 段、部分次新）只返回 `day`（未复权）节点，拿不到可自证口径的 `qfqday`。
这类票在候选池里永远停在 `KLINE_NOT_VERIFIABLE`（「K 线来源或前复权口径未验证」），既不能确认形态，也不属于「数据还没补齐」。

本地通达信 `vipdoc` 的 `.day` 是未复权原始价，但同目录 `T0002\hq_cache\gbbq` 含完整除权除息事件。按通达信除权公式本地推导，即可得到**可自证口径**的前复权序列，补齐这条通道。

## 2. 口径边界（诚实声明）

本来源的前复权不是「响应里带复权标记」，而是**本地推导**：

```
除权除息价 = (前收盘 − 每股现金红利 + 配股价 × 每股配股) / (1 + 每股送转 + 每股配股)
k = 除权除息价 / 前收盘        除权日之前的 K 线乘 k，即得前复权价（后缀积）
```

对账结果（与腾讯 qfq 全市场比对，1769 只 / 437372 个交易日）：整票最大误差 ≤0.01 元占 94.0%，逐日中位误差 0.0000 元。残余偏差来自 `category≠1` 的股本变迁事件与送转比例四舍五入口径。

因此：

- 只有 `gbbq` 索引可用、且复权因子推导成功时，`evidence.adjustmentMethod === 'gbbq-derived'`，才允许声明为 `qfq`；
- `gbbq` 缺失时只能返回**未复权原始价**，口径记 `none`，绝不冒充前复权；
- 只有 `category=1`（除权除息）事件参与复权；除权日之前不存在真实交易日收盘价的事件跳过（与公开实现一致）；
- 除权日排在序列最新交易日之后的事件不参与，避免把最新价错误压低。

## 3. 配置方式（默认关闭）

路径优先级：

1. 环境变量 `STOCK_SENTINEL_TDX_DIR`（**显式空值 = 关闭本来源**，用于测试隔离）；
2. `settings.json` 的 `tdxDir`（设置页「数据维护与 K 线完整性 → 本地通达信数据目录」）；
3. 未配置 → 本来源关闭。

`DEFAULTS.tdxDir = ''`，即默认不读盘。设置页提供「检测本地数据源」按钮，走只读接口 `GET /api/tdx/status`，不触发任何解析。

当前本机实测返回：

```

 "gbbqAvailable":true,"gbbqBytes":5587811,"markets":["sh","sz","bj"]}
```

## 4. 实现清单

| 文件 | 职责 |
| --- | --- |
| `tdx-gbbq.js` | `gbbq` 解密与按代码索引（`assets/gbbq-keys.bin` 为解密密钥表） |
| `tdx-vipdoc.js` | `.day` 解码、`buildQfqFactors` / `applyQfq`、`fetchTdxKline`、`tdxStatus`、`configuredRoot` |
| `kline-source-contract.js` | `SOURCE_CONTRACTS.tdx`（`volumeUnit:'share'`、`amountField:'record[5]'`、`adjustment.declared=QFQ`、`corroborated:['qfq']`、`verifiedFromResponse:true`）与 `adjustment-upgrade` 单向升级豁免 |
| `data.js` | `KLINE_SOURCES = ['tencent','tdx','baidu','sohu','em','sina']`；多源链与落盘判定 |
| `screener-core.js` | 形态复筛来源白名单 `['tencent','tdx']` |
| `settings.js` / `SettingsSection.vue` | 配置项与检测入口 |
| `server.js` | `GET /api/tdx/status`（只读） |

`.day` 记录格式 `<IIIIIfII>`：日期(YYYYMMDD)、开高低收（×100 存整数）、`amount`(float32，元)、`volume`(股)、保留位。
量纲与 `docs/kline-data-standard.md` 一致：**volume 存股、amount 存元**，转换在源适配边界完成，本来源 `volumeScale=1`，调用方不做二次换算。

## 5. 落库判定：`adjustment-upgrade` 单向升级

历史序列可能是其它来源写下的**未复权**数据（如 `tencent/unadjusted`）。此时：

```
authoritative=UNADJUSTED + incoming=QFQ + hasStoredBars
→ status='adjustment-upgrade'，code='KLINE_ADJUSTMENT_UPGRADE_REQUIRED'
→ action='rebuild_required'，allowed=false
```

`allowed=false` 表示不允许逐日追加混写；`canSafelyRebuildUnverifiedSeries` 接受该状态并额外要求 `storedAdjustment===UNADJUSTED`，满足时**整段重建**替换旧序列。方向是单向的：未复权 → 前复权可升级；前复权 → 未复权一律拒绝。

## 6. `disabled` 语义（避免污染源健康）

本地来源「未配置」返回 `evidence.disabled = true`，与「文件缺失」严格区分：

- 不写入 `sourceAttempts`（未配置 ≠ 尝试过）；
- 不参与「全部源不可用」判定（`kline-sync.js` 中 `local && outcome==='empty'` 被排除在 `KLINE_SOURCE_UNAVAILABLE` 之外）；
- 不触发联网源的 `markKlineSourceFail` 熔断。

否则关掉本来源会让「全源不可用」被降级成「源无有效数据」，破坏既有断言。

## 7. 复筛口径：来源可验证 ≠ 样本可交易

来源白名单只是前置快速过滤，仍必须同时满足契约的 `isAdjustmentCorroborated(source, adjustmentType)` 与 `adjustmentType==='qfq'`，再依次过：

- `candles.length >= LOCAL_KLINE_MIN_BARS (150)`：对齐分桶回测样本口径（2026-09-19 更新，见下）；
- 尾日 `=== snapshotDate` 且 `tailStatus === 'confirmed'`。

**上市历史不足 150 根的次新股依旧不可交易**，排除码是 `KLINE_LISTING_TOO_SHORT`（不是 `KLINE_NOT_VERIFIABLE`）。这一步只消掉「拿不到可自证口径」这一数据缺陷；门槛本身由回测支撑决定，不得包装成「次新已可交易」。

门槛从 250 放宽到 150 的依据是 `docs/2026-09-19-60根口径回测支撑验证.md`：60-99 根分桶里 `limit_pullback` v4 直接亏钱、`rsi_low_turn` v4 盈亏比腰斩，150-249 根才两组形态同时为正。放宽发生在同一批历史数据上，不改形态参数与退出规则。

## 10. 已知边界

- 本机 TDX 尾日落后腾讯时，该票会因「K 线尾日与扫描交易日不一致」停在 `pending_kline`，需先更新本地通达信数据；
- `gbbq` 是数据目录下的缓存文件，通达信未下载完整时缺事件，会退化为未复权（口径记 `none`）；
- 桌面版 `tdxDir` 默认值为空，需在设置页填写或由环境变量注入；规则与默认值改动必须重打包才在桌面版生效。

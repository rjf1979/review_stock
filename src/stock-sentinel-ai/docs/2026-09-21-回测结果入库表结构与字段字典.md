# 尾盘买入 → 次日早盘卖出：回测入库表结构与字段字典（v2，含多周期 K 线形态）

> 目标：把回测结果落进智诊盯盘 SQLite，作为**次日上涨概率预测**与**实盘凭据**的数据底座。
> 本文件是建库脚本 `tools/backtest_store.py` 的唯一设计源（DDL 与本文件保持一致）。

---

## 0. 本轮新增（多周期 K 线形态）

需求：5 分钟 / 15 分钟 / 30 分钟 / 60 分钟 K 线形态也要逐笔记录，与日线形态同等对待。

设计结论：

1. **新增 `bt_trade_tf`**：一行 = 一笔尾盘买入 × 一个周期（每笔 4 行），存放该周期在**决策时刻**的结构量与形态标签。
2. **`bt_pattern_def` 改为统一形态字典**：用 `scope` 列区分 `day`（日线）与 `intraday`（分钟级），日线主形态与分钟主形态共用一张表、一套中文名、一套规则版本。
3. **`bt_trade` 增加 4 个周期的主形态摘要列**（`tf5Pattern` / `tf15Pattern` / `tf30Pattern` / `tf60Pattern` + 掩码 + 共振结论），供预测查询直接单表读，不必每次 join。
4. **`bt_stat.dimension` 扩展取值**：`tf5_pattern` / `tf15_pattern` / `tf30_pattern` / `tf60_pattern` / `tf_align`。
5. **形态复用既有注册表，不新造口径**：日线直接复用 `tools/patterns/` 的 25 个图谱形态 + 6 个 Sequoia-X 形态（共 31 条 `@register`）；分钟级复用**同一批形态函数**，把「日」窗口换算成「根」窗口后按周期跑，日线专属形态不参与分钟计算。详见 §5。
6. 每条形态都需通过「样本量 + 分年稳定性」验证后，才把 `usableForDecision` 置 1。

### 0.1 已定的三条口径（2026-09-21）

| 决策点 | 结论 |
| --- | --- |
| 换手率 | 用**当日成交量 ÷ 当日流通股本**计算，流通股本取自**通达信 gbbq 时点股本时间线**（逐日生效，无前视），`turnoverSrc='gbbq_pit'`；该股在 gbbq 里无记录时回退快照股本（`snapshot_const`），取不到则 `missing`。2026-09-21 实测覆盖率 **99.75%**（108,695 / 108,965） |
| 概念题材 | **本版先不做**：`bt_concept_map` 不建表，`conceptTags` / `conceptHeat` 只保留空列（NULL），等后续版本再补 |
| 日线均线形态 | **复用之前的形态**：可直接交易的**信号层**复用 `tools/patterns` 注册表（31 条，可叠加，`dayPatterns`）；**位置层**（震荡/探底/回踩/上升通道…）复用 `tools/day_shape.py` 的 6 类互斥口径（`dayShape` + `channelType` + `pos120`）。两层互补，见 §5.1.1 |

## 1. 数据可用性（先划清能算的范围）

| 周期 | 本机来源 | 覆盖范围 | 每只根数 | 说明 |
| --- | --- | --- | --- | --- |
| 日线 | `data/hsjday`、`D:\new_tdx\vipdoc\*\lday` | 2021-01 ~ 2026-09-18 | — | 5,429,008 笔回测（v2 口径） |
| 5 分钟 | `D:\new_tdx\vipdoc\{sh,sz}\fzline\*.lc5` | 2026-06-12 ~ 2026-09-18 | 3,360 | 70 个交易日 × 48 根 |
| 1 分钟 | `D:\new_tdx\vipdoc\{sh,sz}\minline\*.lc1` | 2026-06-12 ~ 2026-09-18 | 16,800 | 70 个交易日 × 240 根 |
| 15 / 30 / 60 分钟 | **由 1 分钟本地聚合**（5 分钟交叉校验） | 同上 | 1,120 / 560 / 280 | 通达信不落盘 `.lc15/.lc30/.lc60` |

聚合口径已实测验证：`sh600000` 的 1 分钟按「结束时刻归桶」聚成 5 分钟，与原生 `.lc5` 逐根比对
**3,360/3,360 根全部一致**（OHLC 与成交量零差异，无多余、无缺失）。15/30/60 分钟沿用同一归桶规则。

由此得到的硬结论：

- **多周期形态只存在于分钟数据窗口内**：70 个交易日、292,685 笔。日线口径那 5,429,008 笔无法补算多周期形态（本机没有 2021–2026 的分钟历史）。
- **60 分钟线有预热期**：`ma60` 需要 60 根 = 15 个交易日，因此 60 分钟形态有效样本从 2026-07-03 起（约 55 个交易日）。预热不足的样本写 `qualityFlags='warmup'`，统计自动剔除。
- 70 个交易日且落在 2026 年强势段，因此多周期形态本轮只能作为**观察层 / 待验证特征**，不能直接进实盘凭据；等分钟数据扩到 5 年后，同一套字段自动升级为可用（改 `bt_pattern_def.usableForDecision` 即可，不需要重建表）。
- 覆盖不到的笔，`bt_trade` 里 4 个摘要列写 NULL，`bt_trade_tf` 不写行；统计层用 `tfCoverage` 过滤。

## 2. 时间口径与前视控制（多周期形态的关键约束）

1. 通达信分钟线时间戳 = 该根 K 线的**结束**时刻（`1430` 代表 14:29:00–14:30:00）。
2. 决策时刻固定 `asOf = 1430`（尾盘选股基准时点）。**只使用 `endTime <= asOf` 的已收盘 bar**，未完成 bar 一律不进特征。
3. 各周期在 14:30 的最后一根已完成 bar：

| 周期 | 最后一根已完成 bar | 覆盖区间 | 相对 14:30 的滞后 |
| --- | --- | --- | --- |
| 5 分钟 | 14:30 | 14:25–14:30 | 0 |
| 15 分钟 | 14:30 | 14:15–14:30 | 0 |
| 30 分钟 | 14:30 | 14:00–14:30 | 0 |
| 60 分钟 | **14:00** | 13:00–14:00 | 30 分钟 |

   60 分钟天然滞后半小时，是周期本身决定的，不是数据缺失；`lastBarTime` 落库可审计。
4. 日切分沿用通达信原生：11:30 收盘与 13:00 开盘**不拼接**为一根。
5. 跨日边界：形态只在该周期自身的序列上计算，不跨日人为拼接。
6. 时间网格回测（14:30~14:55 买入）里，形态快照**固定取 14:30**，避免用「不同买入时点对应不同形态」污染对比。

## 3. 表清单

| 表名 | 中文名 | 粒度 | 说明 |
| --- | --- | --- | --- |

| `bt_concept_map` | 个股×概念映射 | 股票 × 概念 | **本版不建表**（概念后置），DDL 预留在 §4.9 |
| `bt_pattern_def` | 形态字典 | 形态 ID | **本轮改为统一字典**：日线 + 分钟，含中文名与判定规则 |

| `bt_time_grid` | 买卖时点网格 | 买入时刻 × 卖出时刻 | 26 × 31 |
| `bt_time_marginal` | 时点边际 | 单个时刻 | 买入/卖出时刻的边际收益 |
| `bt_rule` | 规则扫描 | 组合规则 | 阈值组合的命中率与稳定性 |
| `bt_feature_def` | 字段字典 | 表 × 字段 | 中文名、口径、单位、来源（供 App 显示） |

> SQLite 不存储列注释。因此中文名有两条落地路径：建库脚本 DDL 里的 `--` 注释（供人读），以及 `bt_feature_def` 表（供 App 读取显示）。

## 4. 逐表结构

### 4.1 `bt_meta` 库元信息

```sql
CREATE TABLE bt_meta (
  key         TEXT PRIMARY KEY,  -- 配置项名称
  value       TEXT NOT NULL,     -- 配置项取值
  updatedAt   TEXT NOT NULL      -- 更新时间（ISO8601）
);
-- 固定键：schemaVersion / createdAt / generator / tdxMinuteAsOfBars
```

### 4.2 `bt_dataset` 数据集覆盖

```sql
CREATE TABLE bt_dataset (
  datasetId     TEXT PRIMARY KEY, -- 数据集标识（如 kline_day / minute_1m / minute_5m）
  kind          TEXT NOT NULL,    -- 类型：day / minute
  freqMin       INTEGER,          -- 频率（分钟）：日线为 NULL，分钟为 1/5/15/30/60
  source        TEXT NOT NULL,    -- 数据来源（tdx fzline / tdx minline / tdx lday）
  dateMin       INTEGER,          -- 起始交易日 YYYYMMDD
  dateMax       INTEGER,          -- 结束交易日 YYYYMMDD
  tradingDays   INTEGER,          -- 覆盖交易日数
  codeCount     INTEGER,          -- 覆盖股票数
  barsPerCode   INTEGER,          -- 每只股票平均 K 线根数
  missingNote   TEXT,             -- 缺失与空洞说明
  builtAt       TEXT              -- 采集/统计时间
);
```

### 4.3 `bt_run` 回测批次

```sql
CREATE TABLE bt_run (
  runId           INTEGER PRIMARY KEY AUTOINCREMENT, -- 批次号
  runKey          TEXT NOT NULL UNIQUE,              -- 批次可读标识（含日期与口径摘要）
  createdAt       TEXT NOT NULL,                     -- 创建时间
  engineVersion   TEXT NOT NULL,                     -- 回测程序版本
  priceMode       TEXT NOT NULL,                     -- 价格口径：raw(不复权) / qfq / hfq
  buyTime         INTEGER NOT NULL,                  -- 基准买入时刻 HHMM（1430）
  sellTimeStart   INTEGER NOT NULL,                  -- 卖出窗口开始 HHMM（0930）
  sellTimeEnd     INTEGER NOT NULL,                  -- 卖出窗口结束 HHMM（1000）
  costBps         REAL NOT NULL,                     -- 双边成本（0.15 表示 0.15%）
  universeFilter  TEXT NOT NULL,                     -- 股票池过滤说明（个股白名单/排除银行/退市/B股/ST）
  excludeIndustry TEXT,                              -- 排除行业清单（JSON）
  keepDelisted    INTEGER NOT NULL DEFAULT 0,        -- 是否保留退市股（0/1，默认 0）
  paramsJson      TEXT NOT NULL,                     -- 全部口径参数（含时间戳口径说明）
  tradeCount      INTEGER,                           -- 入库笔数
  note            TEXT                               -- 备注
);
```

`paramsJson` 必须包含：`minuteBarTimestamp='end'`、`tfAsOf=1430`、`tfFirstBarRule`、`sellRule`（开盘价/最高价/止盈模型）等，保证口径可复现。

```sql
  ma20Slope      REAL,               -- 20 日均线斜率
  ma60Slope      REAL,               -- 60 日均线斜率
  ma120Slope     REAL,               -- 120 日均线斜率
  maAlign        TEXT,               -- 均线排列：bull_align/bear_align/converge/mixed
```

### 4.5 `bt_trade_tf` 逐笔多周期快照（本轮新增，多周期形态的唯一真源）

```sql
CREATE TABLE bt_trade_tf (
  tradeId        INTEGER NOT NULL,   -- 关联 bt_trade.tradeId
  runId          INTEGER NOT NULL,   -- 关联 bt_run.runId
  period         INTEGER NOT NULL,   -- 周期（分钟）：5 / 15 / 30 / 60
  code           TEXT    NOT NULL,   -- 股票代码
  date           INTEGER NOT NULL,   -- 交易日 YYYYMMDD
  asOf           INTEGER NOT NULL,   -- 快照决策时刻 HHMM（默认 1430）
  lastBarTime    INTEGER,            -- 最后一根已收盘 bar 的结束时刻 HHMM
  barCount       INTEGER,            -- 该周期可用 K 线总根数（判断预热）
  barsToday      INTEGER,            -- 当日该周期已收盘根数
  closeVsMa5Pct  REAL,               -- 收盘相对周期 ma5 偏离 %
  closeVsMa20Pct REAL,               -- 收盘相对周期 ma20 偏离 %
  closeVsMa60Pct REAL,               -- 收盘相对周期 ma60 偏离 %
  ma5SlopePct    REAL,               -- 周期 ma5 斜率（近 5 根 %）
  maAlign        TEXT,               -- 周期均线排列：bull_align/bear_align/converge/mixed
  posInRange20   REAL,               -- 收盘在近 20 根区间的位置 0~1
  posInRange60   REAL,               -- 收盘在近 60 根区间的位置 0~1
  rangeAmp20Pct  REAL,               -- 近 20 根区间振幅 %
  volRatio20     REAL,               -- 最新一根量 ÷ 前 20 根均量
  atrPct14       REAL,               -- 周期 ATR14 / 收盘 %
  rsi14          REAL,               -- 周期 RSI14
  macdHistPct    REAL,               -- 周期 MACD 柱 / 收盘 %
  ret1Pct        REAL,               -- 最近 1 根收益 %
  ret5Pct        REAL,               -- 最近 5 根收益 %
  trendSlopePct  REAL,               -- 近 20 根线性回归斜率（每根 %）
  trendR2        REAL,               -- 近 20 根线性回归 R²（判断通道/箱体）
  patterns       TEXT,               -- 命中形态 ID 列表（复用注册表 ID + 周期后缀，可多命中）
  patternMask    INTEGER,            -- 命中形态位掩码（与 bt_pattern_def.bitIndex 对应）
```

## 5. 形态口径：复用既有注册表

不再自造形态集合。日线与分钟层共用 `tools/patterns/` 注册表（`REGISTRY`），形态定义、中文名、分类、默认参数、说明全部以注册表为唯一真源，`bt_pattern_def` 的种子行直接由注册表元数据灌入。

### 5.1 日线层（`scope='day'`）

注册表共 31 条，全部落库：

- `xingtaidu.py` 25 条图谱形态，5 个分类：
  - 均线启动类：`ma_bullish` 均线多头、`pullback_ma20` 回踩20日线、`ma_golden_start` 金叉启动、`trendline_breakout` 趋势线突破、`macd_water_golden` MACD水上金叉
  - 量价共振类：`volume_breakout` 放量突破、`shrink_stabilize` 缩量企稳、`dry_price_bottom` 地量地价、`consecutive_yang` 连阳启动、`strong_sideways` 强势横盘
  - 短线强势启动：`limit_pullback` 涨停回踩、`fake_break_pack` 假跌破反包、`yang_engulf` 阳包阴、`long_lower_shadow` 长下影企稳、`rsi_low_turn` RSI低位拐头
  - 底部反转类：`double_bottom` 双底(W底)、`rising_w_bottom` W底突破、`arc_bottom` 圆弧底、`head_shoulder_bottom` 头肩底、`second_test` 二次探底
  - 突破爆发类：`platform_breakout` 平台突破、`box_breakout` 箱体突破、`ascending_triangle` 上升三角形、`gap_breakout` 缺口突破、`n_shape` N字突破
- `sequoia_x.py` 6 条：`sqxm_ma_volume`、`sqxm_turtle_trade`、`sqxm_high_tight_flag`、`sqxm_limit_up_shakeout`、`sqxm_uptrend_limit_down`、`sqxm_rps_breakout`

落库方式：`dayPatterns`（命中 ID 列表，可多命中，符合注册表定义）、`dayPatternMask`（位掩码）、`dayCategories`（命中的分类集合）。不设"互斥主形态"，避免把本来可以叠加的证据强行归一。

#### 5.1.1 日线均线形态位置（`dayShape` / `channelType` / `posInRange120`）

`bt_trade.dayShape` 是**互斥单值**列（与可叠加的 `dayPatterns` 互补），由 `tools/day_shape.py` 判定，口径固定为：

1. 先看 120 日通道：`pos120 = (close − ll120) / (hh120 − ll120)`，再按 `ma5/ma10/ma20/ma60` 排列与斜率组合判定；
2. 顺序**互斥**（先命中先返回）：`上升通道` → `下降通道` → `高位横盘` → `探底形态` → `波动回踩` → `震荡形态`（兜底）；
3. 数据不足（根数不够算 120 日通道）返回 `未知`，`channelType='na'`、`posInRange120=NULL`；
4. `channelType` ∈ {`up`,`down`,`box`,`na`}：20 根最小二乘回归的口 R² ≥ 0.5 判方向（斜率为正 `up`、为负 `down`），否则 `box`；数据不足为 `na`。
   `channelType` 与 `dayShape` **同时**判定（同一次调用返回），但不是一一映射：`box` 可能落在 `震荡形态`/`高位横盘`/`探底形态`/`波动回踩` 中的任意一类。

落地情况：

- 多周期批次（runId=10，2026-06-12~09-17 / 69 日 / 292,685 笔）三列在 `bt_trade` 内逐笔写入；
- 日线批次（runId=1）三列由 `tools/day_shape_scan.py` 在本地通达信日线上重算后回填，
  覆盖 **2% 抽样本 108,965 笔**（合计恰等于明细表 `bt_trade` 的 108,965 行，无遗漏），并产出 `bucket_day_shape.csv` / `bucket_channel.csv` / `bucket_pos120.csv`
  供 `backtest_store.py --import-daily` 导入为 `bt_stat` 维度。

该列只用于「形态位置」分桶（`bucket_day_shape.csv` / `bucket_channel.csv`），**不参与** `patterns` 注册表命中集合，两套口径不混用。

### 5.2 分钟层（`scope='intraday'`，周期 5/15/30/60）

复用**同一批形态函数**：把该周期的 K 线喂给 `indicators.compute_indicators()`，再调 `patterns.detect()`。窗口是「根」而不是「日」，其余逻辑不改。形态 ID 加周期后缀（`ma_bullish@15`、`volume_breakout@60`），在 `bt_pattern_def` 里各占一行，参数写 `ruleParams`。

| 适配等级 | 形态 | 处理 |
| --- | --- | --- |
| A 原样复用（窗口按根） | 均线启动类 5 条、量价共振类 5 条、`fake_break_pack`、`yang_engulf`、`long_lower_shadow`、`rsi_low_turn`、`gap_breakout`、`n_shape`、`sqxm_ma_volume`、`sqxm_high_tight_flag`、`sqxm_turtle_trade` | 纯价量/均线/量能逻辑，与周期无关，参数照搬 |
| B 需放大窗口 | `double_bottom`、`rising_w_bottom`、`arc_bottom`、`head_shoulder_bottom`、`second_test`、`platform_breakout`、`box_breakout`、`ascending_triangle` | 日内根数不够成形，窗口按跨日根数放大（如 5 分钟 W 底取近 240 根 ≈ 5 个交易日），每个周期单独写参数 |
| C 日线专属，不生成 | `limit_pullback`、`sqxm_limit_up_shakeout`、`sqxm_uptrend_limit_down`（依赖涨停判定，单根分钟线不可能有 10%）、`sqxm_rps_breakout`（依赖全市场横截面排名） | 在分钟序列上恒为 False 或语义失效，直接跳过，不写伪造字段 |

A/B/C 分级以「窗口能否在日内根数内成形」为准，实施时逐条核对函数体并写单测固定命中集合。

除注册表形态外，分钟层额外记录周期结构量，用于将来重新分桶：`closeVsMa5Pct`/`closeVsMa20Pct`/`closeVsMa60Pct`、`ma5SlopePct`、`posInRange20`/`posInRange60`、`rangeAmp20Pct`、`volRatio20`、`atrPct14`、`rsi14`、`macdHistPct`、`ret1Pct`/`ret5Pct`、`trendSlopePct`、`trendR2`、`barCount`。

### 5.3 指标来源与基准过滤

分钟层复用 `tools/indicators.compute_indicators()`（ma5…ma250、vma5/20/60、hh/ll、macd、kdj、boll、rsi14、atr14 现成）。`_ctx_filter` 的基准相关过滤（`rs_*` / `bench_ma_*`）在分钟层默认**不注入** `bench_close`，按函数定义自动不生效；若后续要启用，需按 `(date, time)` 对齐注入指数分钟序列。形态判定全部基于 `endTime <= 1430` 的已收盘 bar（详见 §2）。

### 5.4 形态验证要求

每条形态 × 每个周期都要出 `sampleCnt / hit3Pct / lift / 分年命中率`，写回 `bt_pattern_def` 的 `evidence*` 列。样本不足或逐年不稳的一律保持 `usableForDecision=0`，只做参考、不进实盘凭据。

## 7. 口径决策记录

已定（2026-09-21）：

1. **换手率** = 当日成交量 ÷ **当日**流通股本 × 100。流通股本主口径来自通达信 `gbbq` 解密后的时点股本时间线（`gbbq_pit`，逐日生效、无前视），gbbq 无记录的个股回退快照股本并标记 `snapshot_const`，两者都取不到标记 `missing`。2026-09-21 实测抽样本覆盖率 99.75%（108,695 / 108,965，missing 270）。**v1 的 `floatcap_approx`（统一用 2026-09-18 快照股本）已弃用**：它会让送转/增发前后的换手率失真，属于前视偏差。解析与校验见 `tools/gbbq.py`、`tools/float_shares.py --verify`。

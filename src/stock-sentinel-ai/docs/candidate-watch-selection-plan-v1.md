# 候选池到盯盘的选股方案 v1

日期：2026-09-06
范围：仅智诊盯盘 `src/stock-sentinel-ai/`；Web 固定端口 3110。
状态：方案已落盘，推荐引擎、SQLite 推荐记录及页面联动待实现。本文不是已上线功能说明。

## 目标与现状

从全部候选股中评估哪些值得盯盘，而非先由人工挑选几只再为其寻找理由。允许没有优先盯盘对象，不设必须选满的数量。

本次确认候选池 48 只、盯盘 0 只；天邦食品、傲农生物、引力传媒已回迁，重复股票去重，K 线及研判记录保留。数量为当前状态，不写死在程序中。

现有 `trackRecommendation` 主要按量能分与 AI verdict 分类，且把未研判、数据不足归入排除；它只作为迁移前逻辑，不能代表本方案已经完成。

## 完整流程

市场预扫描（行业与概念） -> 快照预筛 -> 候选池 -> 补齐 K 线与日期校验 -> 形态复筛与风险评估 -> 候选池推荐 -> 人工确认转入盯盘 -> 跟踪条件与操作方案。

扫描阶段不以缺少 K 线剔除快照命中。候选池保留全部股票，推荐仅改变分类、排序与解释。本文中的后置形态复筛顺序优先于旧扫描文档中把形态确认前置的描述。

## 分类规则

按数据有效性、风险门槛、证据完整程度顺序判断，程序给出最终分类，AI 不能覆盖硬门槛。

| 分类 | 判断 | 后续动作 |
| --- | --- | --- |
| 数据不足 | 必需行情、K 线、板块证据缺失、过期或日期冲突 | 列出缺失项与补齐动作，不能视为差股票 |
| 暂不推荐 | 数据足够，但形态不适配、趋势破坏、压力空间不足或风险不满足策略 | 显示具体原因和重新评估条件 |
| 等待确认 | 有题材与技术依据，但量能、价格位置或确认信号未满足 | 明确等待的条件、观察期限与失效条件 |
| 优先盯盘 | 数据有效、市场策略适配、题材与量价证据支持、风险收益空间合格 | 展示入选理由和重点跟踪条件，允许人工转入盯盘 |

弱势退潮默认最高为等待确认；后续只有经过验证的环境适配规则才能开放例外。量能高分、单个形态命中、AI 的 maintain 结论均不能单独晋级。

## 证据与计算

复用 `market-regime.js`、`screener-core.js`、`indicators.js`、`price-levels.js`，不重复实现技术指标。

- 市场：环境、置信度、广度与情绪结构、适用策略。
- 行业与概念：真实归属、资金与扩散证据、证据日期；仅属于热门概念不足以入选。
- 个股：形态、趋势、量价、流动性、相对强弱、压力支撑、跳空及价格透支风险。
- 风险收益比：按计划入场价、有效止损位、第一目标计算；要求止损 < 入场 < 目标。缺失或位置不合理时不可评分，禁止虚构价位。
- 推荐规则与阈值版本化。第一版沿用已验证的规则参数；尚无依据的新阈值先回放验证，不声称存在获利概率或确定收益。

先通过硬门槛，再按证据质量、风险收益空间、形态与题材强度排序；并列时用证券代码保证稳定顺序。首版不增加任意加权综合分。

同题材股票展示比较依据与集中风险；可标记优先观察对象，但不因同题材直接删除其他候选，也不把跨概念重复归属算成多份独立证据。

## 每只股票的推荐方案

固定输出：推荐分类、主要理由、反对证据、所属行业与概念、当前形态、观察触发条件、失效条件、风险收益依据、缺失数据、证据时间与推荐版本。

触发条件须说明价格、量能、持续时间及盘中或收盘确认口径。只有日 K 线时不得声称已确认盘中持续放量等条件。

AI 根据结构化证据解释理由、组织操作建议；价格和指标由程序计算并校验。用户未保存 Prompt 时不调用 AI。AI 失败或未配置时，规则分类可展示并注明解释未生成，不隐藏已有结果。

候选池阶段不输出依赖账户资金的具体下单数量。转入盯盘后，结合持仓、成本、单笔风险和可卖数量生成操作方案；支持 A 股交易单位与 T+1 限制。

## 页面与动作

在现有候选池页增加“评估盯盘价值”按钮，支持全部候选评估、进度、取消与失败重试；已有结果时显示“重新评估”。

列表增加推荐分类、核心理由、待触发条件、风险摘要、评估日期。顶部按全部、优先盯盘、等待确认、暂不推荐、数据不足过滤，默认显示全部。展开行显示完整方案与证据。任何分类均可查看股票详情。

“转入盯盘”由用户明确操作；重新评估不自动转移或删除股票。结果成功落库后才更新页面，失败保留上次结果并标记过期或失败状态。刷新页面恢复当前视图与已保存结果。

## 持久化与业务联动

使用项目现有 SQLite 写入队列与事务方式，新增推荐批次与单股推荐版本记录。字段至少包括 batchId、code、classification、reasonCodes、evidenceJson、conditionsJson、missingJson、ruleVersion、promptVersion、evidenceHash、createdAt、status。

批次固定候选范围与证据版本，逐股记录结果；取消保留已完成项。重复请求合并，禁止重叠批次覆盖彼此。候选移除后不因任务完成自动加回。

行情、K 线、市场与板块证据、规则、交易方式或 Prompt 变化时标记对应评估需要更新。刷新只是读取，不能每次触发 AI。

候选池与盯盘双向迁移沿用证券代码关联 K 线、AI 记录和推荐历史；确认目标列表保存成功后再移出原列表。已有记录去重合并，不能清除分析数据。

## 数据前置修正

目前盯盘曾以最后 K 线日期为另一份快照贴日期，该做法不足以验证数据一致性。必须分别保存行情真实时间、交易日期、抓取时间与复权口径；本地最新数据不得自动称为最新交易日收盘数据。

校验交易日历、停牌、节假日、盘中与收盘完整性。陈旧 K 线不得给新快照赋日期；不同日期字段不得混合计算。缺少可靠日期时明确降级，保留原始证据，不修改历史文件来掩盖冲突。

## 实施与验收

1. 修正数据有效性判断，建立推荐契约与 SQLite 记录，迁移现有分类语义。
2. 实现规则评估、证据排序及单股方案；验证无 K 线、陈旧数据、弱势行情、压力空间不足、有效确认与重复题材样例。
3. 接入候选池页面与批次控制，保持全部股票可见，完成日期、失败、空结果反馈。
4. 接入用户已配置的 AI 解释与转盯盘记录关联，验证 Prompt 必填、失败保留、取消重试、刷新恢复和双向迁移。
5. 在 3110 验证现有候选池全流程；测试隔离数据不得改写用户候选、盯盘或设置。桌面与移动视口、键盘焦点、加载、空数据、错误和减少动画状态完成验收。

验收不要求推荐特定数量或强制产生买入结论。首版完成标准是每只候选都有可追溯分类，优先盯盘对象有明确理由及跟踪条件，用户可据此挑选，再进入操作方案阶段。

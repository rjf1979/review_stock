# A 股每日行情复盘

## 目标

将多个公开行情源的原始响应转换为可审计、可复现、可直接渲染的收盘复盘。默认分析最近一个已收盘交易日；指定日期时必须使用该日期的历史快照，不能以当前实时数据冒充历史数据。

生成前按需读取：

- 数据源、降级链和字段映射：[references/data-sources.md](references/data-sources.md)
- 结构化数据契约：[references/report-schema.md](references/report-schema.md)
- 18 日报告视觉与验收基线：[references/report-layout.md](references/report-layout.md)

## 强制原则

- 只使用 API 返回或确定性计算的数据，禁止猜测和补齐缺失数字。
- 免费公开数据源优先；每个关键字段记录来源、抓取时间、交易日期和口径。
- 交易日 15:10 前只能生成盘中快照；正式收盘报告必须使用 15:00 后数据。
- 历史日期的接口若只返回当前行情，该结果必须拒绝。
- 资金流只允许同一供应商内排序，不跨供应商直接比较。
- 核心字段缺失时返回 `null` 与原因，不将局部 100 条样本称为全市场。
- 本项目的日报输入、分析和输出均不依赖额外榜单数据。

## 采集工作流

1. 确定 `requested_date`、实际 `trade_date`、`as_of` 和 `report_mode`。
2. 获取全市场普通 A 股快照，排除 ETF、基金、债券、B 股、退市证券和停牌股票。
3. 获取主要指数、当日与前一交易日成交额。
4. 获取当日涨停池、跌停池、炸板池及最近三个交易日涨停池。
5. 由连续交易日涨停池计算板高分布、最高高度和昨日涨停晋级率。
6. 获取行业/概念涨跌、上涨下跌家数、资金流和热点归因。
7. 标准化字段并执行真实性校验。
8. 数据达标后计算市场温度、主线与次日观察锚点。
9. 按 18 日基准渲染 HTML，并完成桌面、移动和打印检查。

单个非关键端点失败不应丢弃整份报告。对同一端点最多重试三次并指数退避；失败字段明确降级。

## 数据真实性校验

- 上涨家数 + 下跌家数 + 平盘家数 = 有效交易股票数。
- 全市场有效样本通常应大于 5,000；少于 1,000 时一律判为无效广度。
- 涨停、跌停家数不得大于有效交易数。
- 炸板股票必须满足盘中触及涨停且收盘未封住。
- 成交额、指数、池数据的交易日期必须等于 `trade_date`。
- 连板按连续交易日计算，断板后重新计数。
- 封板率分母为涨停数 + 炸板数；分母为零时返回 `null`。
- 昨日涨停晋级率分母只包含今日正常交易的昨日涨停股票。
- 核心汇总指标需要一个权威来源或两个独立上游一致；同一上游的封装与直连不算双源。
- 全市场成交额跨源相对偏差不超过 1%；家数类偏差不超过 3 家。

缺少全市场快照、涨跌停状态、昨日涨停名单、主要指数中的任意两类时停止评分，只生成数据质量报告。

## 指标口径

```text
有效交易数 = 上涨家数 + 下跌家数 + 平盘家数
红盘率 = 上涨家数 / 有效交易数
成交额变化 = 当日成交额 - 前一交易日成交额
成交额变化率 = 成交额变化 / 前一交易日成交额
封板率 = 涨停家数 / (涨停家数 + 炸板家数)
炸板率 = 炸板家数 / (涨停家数 + 炸板家数)
连板晋级率 = 今日成功晋级数 / 昨日涨停且今日正常交易数
最高高度 = 今日连续涨停天数最大值
```

市场温度为 0 至 100：

```text
广度分 = min(红盘率 / 0.80, 1) * 25
涨停分 = min(涨停家数 / 120, 1) * 20
封板分 = min(封板率 / 0.85, 1) * 15
高度分 = min(最高高度 / 8, 1) * 15
晋级分 = min(晋级率 / 0.65, 1) * 10
主线分 = 宽度、资金、高度各 0 或 5
最终温度 = clamp(各项之和 - 风险扣分, 0, 100)
```

分区：0-20 冰点、21-40 低迷、41-60 修复、61-75 活跃、76-85 高温、86-100 过热。

## 主线识别

不把涨幅第一直接定义为主线。候选方向按宽度 30%、高度 20%、强度 20%、资金 20%、持续性 10% 计算。

标记主线至少满足：

- 综合分不低于 70；
- 至少三只涨停，或拥有全市场唯一最高板；
- 宽度、高度、资金三项中至少两项进入候选方向前 20%。

三项均进入前 20% 才能写“三维共振”；只有一项突出时写“局部强势，暂不确认主线”。资金缺失时不得用涨幅代替。

## 输出要求

- 结构化输出必须符合 `references/report-schema.md`。
- 自然语言结论中的每个数字都能回溯到结构化字段。
- 观察锚点只描述次日可验证条件，不预测涨跌。
- 报告显式标注缺失字段、质量等级和数据截至时间。
- 不给出个股买卖建议，不使用确定性收益措辞。

## AI 输出契约

当前生成服务只接受纯 JSON，不得输出 Markdown、代码块或额外说明。必须且只能返回：

- `title`：字符串。
- `temperature`：0 至 100 的整数；评分证据不足时为 `null`。
- `summary`：可由输入证据核验的收盘结论。
- `marketStage`：市场温度分区或“数据待补充”。
- `mainline`：主线结论；未达到确认条件时明确写“未确认”。
- `nextFocus`：最多 12 条可在下一交易日验证的观察条件。
- `warnings`：最多 12 条数据缺失、冲突或风险说明。
- `dataQuality`：只能是 `high`、`medium` 或 `low`。

只使用调用方 `evidence.market` 中的输入。结构化契约中存在但输入未提供的字段必须视为 `null` 或空数组，不得借助常识、历史报告或想象补齐。自然语言中的每个数字都必须能回溯到输入字段。

| 数据 | 主源 | 验证或备用 | 实现提示 |
|---|---|---|---|
| 全市场广度、成交额 | 东方财富 `clist/get` 分页 | 新浪全市场快照 | 东财单页上限通常为 100，必须读取 `data.total` 后逐页拉取 |
| 主要指数 | 腾讯财经 | 东方财富指数历史行情 | 腾讯返回 GBK，必须按 GBK 解码 |

| 跌停池 | 东方财富 `getTopicDTPool` | 全市场快照按跌停价复算 | 排除非普通 A 股品种 |
| 炸板池 | 东方财富 `getTopicZBPool` | 最高价与涨停价复算 | 收盘仍封板的股票不得计入 |
| 连板高度 | 最近三日涨停池自行计算 | 池字段 `zttj.days` | 以连续交易日为准，不按自然日 |
| 行业涨跌与资金 | 东方财富行业 `clist/get` | 成分股聚合 | 主力净流入字段 `f62`，仅作同源排序 |
| 热点归因 | 同花顺热点 | 东方财富概念成分 | 题材原因是文本证据，不把缺失涨幅解析成 0% |

## 东方财富池接口

公共基础地址：`https://push2ex.eastmoney.com/`。

- 涨停：`getTopicZTPool`
- 跌停：`getTopicDTPool`
- 炸板：`getTopicZBPool`

共同参数包括 `date=YYYYMMDD`、`Pageindex=0`、`pagesize`、`dpt=wz.ztzt`。响应成功需满足 `rc=0`，记录在 `data.pool`，总数在 `data.tc`。

常用字段：

- `c` 代码、`n` 名称、`zdp` 涨跌幅、`amount` 成交额。
- `hybk` 行业、`fund` 主力净流入、`fbt` 首次封板、`lbt` 最后封板。
- `zbc` 炸板次数、`lbc` 连板数、`zttj.days` 统计窗口、`zttj.ct` 连续次数。

接口属于东财独有数据，串行调用并限制频率。缓存收盘和历史响应；相同日期不要反复抓取。

## 全市场分页

`push2.eastmoney.com/api/qt/clist/get` 的 `pz=6000` 不代表会返回 6000 条。实现必须：

1. 以 `pz=100` 请求第一页。
2. 读取 `data.total`。
3. 逐页获取直到累计记录达到 `total` 或页面为空。
4. 按证券代码去重。
5. 校验累计样本不少于 5,000，且总数与 `data.total` 差异在可解释范围内。

东财请求必须串行；两次请求间隔建议至少 800-1,200ms。分页失败时保留已抓取页用于诊断，但不能作为全市场统计。

## 历史日期保护

- 接口响应没有日期时，不能自动认定为请求日期。
- 当前行情接口只用于当前交易日；历史报告必须读取带日期的历史端点或已持久化快照。
- 任何日期不一致都写入 `quality.conflicts` 并拒绝相应字段。

## 同花顺热点解析

热点接口返回字段可能为字符串、百分号文本或空值。空值不是 0；解析失败时使用 `null`。题材聚合优先按 `reason` 拆分关键词并计数，同时保留股票代码便于与涨停池交叉验证。

# 2026-08-18 报告视觉基线

## 固定层级

1. 顶部信息条：报告名称、交易日期、数据截至时间、打印按钮。
2. 首屏三栏：市场温度、主线结论、红盘率/涨跌停/成交额。
3. 情绪指标：涨停、炸板、封板率、最高高度、晋级率。
4. 广度与指数：涨跌家数、广度条、成交额变化、五个主要指数。
5. 主线三维证据：宽度、高度、资金与候选方向比较。
6. 连板梯队：完整板高分布、市场高度与主线高度对比。
7. 明日观察锚点：四项可验证条件。
8. 结论、数据截至时间和免责声明。

缺失数据应保留所在位置并显示“待补充”，不能删除整个区块造成版式不对称，也不能填入历史日期的数字。

## 视觉语言

- 信息密集的金融报告，浅灰页面背景、白色整页容器、8px 圆角。
- 红色表示上涨，绿色表示下跌；文字状态同时注明涨跌，不能只靠颜色。
- 仅使用一个主强调色体系，不使用渐变球、玻璃拟态或营销页构图。
- 区块以边线和留白分组，不使用卡片套卡片。
- 数字使用等宽数字特性，表格列保持稳定。

## 响应式与可访问性

- 桌面首屏三栏；820px 以下两栏并将行情带置于下一行；560px 以下单列。
- 移动端核心数据表允许合理换行，不能导致整页横向滚动。
- 打印使用高对比浅色主题，隐藏打印按钮，避免区块跨页断裂。
- 提供跳到主体链接、语义标题、可见键盘焦点。
- 正文移动端至少 16px，按钮触控高度至少 44px。
- 尊重 `prefers-reduced-motion`；报告默认不需要装饰动画。

## 验收

- 检查 375、768、1024、1440px。
- 检查温度为 `null`、数组为空、长标题、长风险提示。
- 检查打印预览与缩放 200%。
- 检查页面无水平溢出、文字不遮挡、数据区块不因内容变化跳动。
